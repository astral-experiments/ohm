# Default DWARF4 and experimental DWARF5

On an x86-64 release-14 Ruff `cargo +ohm build`, DWARF5 reduced debug relocations in a single-CGU formatter-fixtures object from 21,870 to 11,578. The entire CLI ELF grew from 160,333,672 to 227,909,120 bytes. In every one of the six default workspace executables, all allocatable code and data retained the same section sizes, addresses, flags, alignments and bytes across both encodings, except the GNU build ID. Each encoding kept its own complete raw native ELF oracles. A Rust inline-stack probe reported the same original source lines in GDB 15.1 and the standard backtrace in both versions.

We paired unqualified warm rebuilds of the Ruff CLI in eight randomized blocks, with four original and four changed source states and four of each arm order. Every command matched its six corresponding native oracles and rebuilt only `ruff` among 501 units. DWARF4 took a median 1.625 seconds and DWARF5 took 1.772 seconds. Across paired ratios, DWARF5 increased elapsed time by 10.73% (six of eight slower, exact two-sided p = 0.180) and child CPU by 20.90% (seven of eight slower, p = 0.015625). We rejected this candidate at the screen and left Linux’s default debugging format unchanged. [Order and affinity](dwarf5-screen-plan.json) · [Raw whole-command times](dwarf5-screen.jsonl)

A separate historical formatter-fixture edit changed the linked addresses in all 1,149 `.debug_info` and `.debug_aranges` units. Only 233 of 1,149 `.debug_line` units retained identical raw bytes. The byte comparisons used the complete reverse of Ruff `2fb7c8ddd8` against `93526150df` with a sensitivity build of the authentic harness-free fixture and captured release dependencies.
