# Ohm ablation coverage and dispositions

All report ablation candidates are covered by a measured comparison, a source disposition, or an explicit held/unavailable result. Twenty-three timing campaigns have final independent root acceptance. The separate Mono Ruff/uv block also has final independent acceptance for four pairs; Mono’s coherent removal is held because no Codex pair is accepted. No further review timing is planned. The comprehensive source review is [the stack report](../stack-review/full-report.md). This record states the present evidence and recommendation for each ablation axis.

Primary measurements are representative `cargo check`, `cargo build`, `cargo clippy` and `cargo fmt` commands on Ruff, uv and Codex. Cold, warm no-op and edited states are separate; history totals are secondary. Project tests are not executed in the timing samples. Individual reports define the accepted source/native/runtime/training controls and their correctness limits; identical binaries reuse those proofs when moving hosts. Future implementation and combined-stack validation are separate adoption work.

Cargo #104 and #115 are removed from the active Cargo stack, with dependent heads updated and clear PR comments. Historical release manifests and tags are unchanged. Both timing arms retain identical original Cargo bytes from the frozen shipping control. [Removal record](cargo-removal.md).

Every accepted comparison contains the assignments declared by its immutable schedule. Existing formatter, Serial, cache-bundle and Dense campaigns use six pairs per project; newer screens use two opposite orders. Both orders for a project remain wholly on one host, including split-host campaigns. A rejected whole pair is excluded without reusing partial cells or replacing an accepted slot for its speed. Maximum-child RSS is not aggregate memory; endpoint allocated bytes are not peak disk use. Raw slower results, all failed attempts and exact ownership release evidence remain retained.

The final method uses the original quiet and continuous-monitor thresholds. A prospective amendment bounds waiting for a complete passing six-by-five-second quiet window to 270 seconds, retaining every unsuccessful untimed window; prepared/post-cleanup gates retain their fixed 30-second cooldown. It changes waiting only, with no timed-command retry or threshold relaxation. [Initial/prepared approval](benchmarks/initial-prepared-full-quiet-wait-proposal-01/root-review-01.json), [post-cleanup approval](benchmarks/post-cleanup-full-quiet-wait-proposal-01/root-review-01.json), [two-pair screen method](benchmarks/prospective-two-pair-screen.md).

Earlier whole-session attempts are historical method evidence. They exposed a shared Codex temporary-directory/socket/umask fault, which was repaired and checked with the existing binaries; later ordinary-command timing does not execute those project tests. Their partial cells, later contention failures and the formatter replay interrupted by the scope change remain excluded. They do not create a promise to rerun full suites or complete sessions.

The [small-patch appendix](../stack-review/source-dispositions.md) gives explicit upstream/drop/fold decisions for Rust #85/#100/#108 and the #104/#112 remainder, Clippy #41, rustfmt #17 and Cargo #105, and verifies 25 empty frozen layers. These source questions have no prescribed independent timing arm and are not described as freshly measured. Historical proposals to split every cache or automatically expand screens are superseded by this review’s representative-command scope and explicit held dispositions.
