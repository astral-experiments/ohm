# Ohm simplification: ablation findings

This is the evidence and disposition record. Each report candidate has a measured comparison, a source recommendation, or an explicit held/unavailable result. The comprehensive source review is [the stack report](../stack-review/full-report.md); [progress](progress.md) records every remaining comparison. Fresh measurements use the fixed Ohm 1.99.0-1 sources and matched optimized runtimes. Historical PR measurements remain identified as historical evidence in the source report.

The decision rule is to retain complexity when its practical value justifies owning it across upstream updates. A small positive result does not establish that case. Removing a feature means removing its protocol or specialization coherently, while retaining correctness inputs needed by the features that survive.

## Cargo #96: superseded concurrent reuse

The removal is three production files, +13/-149. It keeps shared-cache writer reservations, lock ownership, admission and deadlock handling.

At the fixed shipping source, eligible units must be immutable shared registry libraries with no dependencies, under fine-grain Build/Check compilation. Every such unit is reserved before freshness observation. When preflight finds a stale unit requiring a writer, Cargo releases the preparatory runner, reacquires exclusive leases and prepares again. The reserved lock operations retain those leases. Another cooperating Cargo producer therefore cannot complete the same physical unit between dirty preparation and the queued recheck.

The real uv probe used two independent worktrees/targets and an initially empty shared store. Its dependency-free `regex-syntax` 0.8.11 check unit compiled once in both variants; the other target was initially Fresh. Both variants pass 66 of the 69 selected shared-cache tests with the same three known failures, and all 33 worktree tests pass. These are retained subsets, not the entire Cargo testsuite.

The first probe set `RUST_LOG`, while this Cargo reads `CARGO_LOG`. Absence of a debug message in that attempt cannot establish recheck-call counts. The conclusion instead rests on source control flow and actual initial freshness/compilation records. A corrected-log probe is separate corroboration. This does not claim the callback never executes, that overhead is zero, or that the conclusion covers noncooperating writers and future locking changes. [Independent source/native review](cargo96/native-raw-01/independent-review.json).

## Coverage and measurement limits

Twenty-three timing campaigns have final root acceptance. All report ablation candidates remain in scope. Primary timing measures ordinary representative `cargo check`, `cargo build`, `cargo clippy` and `cargo fmt` commands on real Ruff, uv and Codex sources. Each command's clean, warm no-op and edited-state cost is reported separately; history totals are secondary context. The compiler recipe has five such commands: cold compilation, warm no-op and one compile after each of three original edits. Compiler check/build timing preserves the original source/configuration history and uses selected library targets. Clippy timing keeps the original representative lint commands, including their `--all-targets` or `--tests` options; those targets are linted and compiled as required, but tests are never executed. Ruff selects the ty libraries, uv selects `uv-pypi-types`/`uv-client`, and Codex selects its TUI library; these results do not measure every workflow in each repository. The `--lib` builds measure library code generation, without final CLI executable linking. uv's third edit changes tests and may be inactive for the selected `--lib` commands; report that phase as a no-op when inactive. Individual reports specify the accepted source/native/runtime/training proofs and their correctness limits; identical binaries reuse those proofs on host changes. A combined implementation needs its own adoption validation, separately from this review.

The four accepted formatter campaigns (#18, #19, package-only and PGO-OFF) each ran 612 ordinary formatting commands with zero project test starts. Command elapsed time totals 19.76 / 19.84 / 17.23 / 17.54 minutes; their first-to-last monitor records span 25.20 / 25.41 / 22.24 / 22.54 minutes. These recorded spans exclude installation, compiler builds, native validation, prefetch and rejected attempts, and are not exact supervisor durations. [Earlier bound accounting](benchmarks/formatter-accepted-duration-accounting.json), [root recomputation](benchmarks/formatter-accepted-duration-root-review.json) and [PGO accounting](benchmarks/rustfmt-pgo-results.md) preserve that distinction. The #118 optimized compiler build separately took 88.25 minutes; this is one setup run, not a counterbalanced pipeline-speed or command-performance comparison.
