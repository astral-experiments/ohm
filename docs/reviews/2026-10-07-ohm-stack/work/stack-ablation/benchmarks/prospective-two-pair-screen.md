# New-candidate representative command screen

This amendment applies only to candidates whose accepted timing campaign has not begun. Existing six-slot campaigns retain their original schedule and completion requirement. No accepted or rejected historical receipt is rewritten, pooled into a new schedule or selected according to its speed.

For a new candidate, predeclare two independent pairs in each of Ruff, uv and Codex: one full-then-reduced and one reduced-then-full. Retain the original representative command recipe, source edits, eight jobs, independent empty histories and paired correctness comparison. Native and optimized-build evidence remains mandatory and is reused for identical binaries. No project test suite runs in timed commands.

Both pairs must pass the unchanged quiet thresholds and continuous monitoring gates. The prospective waiting amendment admits timing only after a complete passing original quiet window, within a fixed bound at initial, prepared and post-cleanup admission. Reject a whole failed pair and retain its complete evidence; any new attempt preserves that slot and order. Report both paired values and their range. Label the results as a two-pair screen, without confidence intervals, significance claims or a six-pair campaign claim.

The screen asks whether the observed command costs justify the source complexity and maintenance burden. A small positive result can still support removal. When disagreement, host variability or an observed effect leaves the recommendation unresolved, freeze a separate six-pair campaign before its timing begins. Preserve and report the original screen separately, including both accepted pairs and all rejected attempts. The current helper does not admit changing a started campaign's shape or pooling its screen into a larger schedule. A material result that clearly supports retention can be reported with the two-pair limit stated, rather than repeating commands solely to obtain a larger sample count.

All report candidates remain in scope, including conditional workflows. An inactive feature or an unavailable platform receives an explicit source/activation finding and an unmeasured disposition. It is never counted as measured or silently folded into another candidate.

The source-bound schedule helper must admit this exact new two-slot shape, retain the existing six-slot contract and forbid changing an already started campaign's declared shape. Actual runtime readiness and current host ownership are still required before timing.
