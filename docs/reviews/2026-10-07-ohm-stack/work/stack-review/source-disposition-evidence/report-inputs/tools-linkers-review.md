# Ohm tools and linker divergence review

Reviewed October 5, 2026. This is a review of the shipped 1.99.0-1 tools and the separate, currently unshipped Wild and macOS linker experiments. No source changes, tests, or performance reruns were made. Current GitHub PR metadata, exact shipped-tree comparisons, implementation files, and checked-in benchmark reports were read. Performance observations below retain their original scope; none should be added across experiments.

## Decisions that remove the most unnecessary complexity

1. **Archive both macOS linker implementations as research; keep them out of the release and cease maintaining their optimization stacks.** The current standalone implementation is 10,307 Rust source lines plus 1,922 integration-test lines. Its exploratory complete-session measurements show +4.28% command time for uv and +2.00% for Ruff/ty, despite substantially faster summed link waits. The older retained/server/disk implementation adds 11,409 source lines plus 3,854 test lines, multiple cache policies and protocols, and did not beat Apple on the prepared Codex rendering workload. Preserving recoverable Git refs and evidence is sufficient; shipping or keeping these stacks continuously rebased is not justified.
2. **Do not introduce the old Wild optimization fork.** Most steps have small memory/instruction improvements with inconclusive latency effects. The strongest results are isolated warm tmpfs links, while the final full-session report has no clear uv speedup, a small Ruff slowdown, and incomplete Codex evidence. Continue bundling upstream Wild. Upstreaming a few tiny, portable patches would be a cleaner path than keeping a 16-step local stack.
3. **Remove rustfmt multi-leaf batching, and challenge the whole per-module certificate layer.** Multi-leaf batching adds +424/−95 lines for a measured 4.3 ms synthetic saving. The single-module feature adds +1,730/−65 and a second native-resolver/certificate mode. Its older real Codex benefits are meaningful, so a package-only removal comparison is needed before dropping all of it. The full formatter fork is +6,291/−723 lines versus the exact upstream tree; this is a much larger divergence than its description suggests.
4. **Remove the Clippy empty-attribute MSRV experiment.** It is six added lines, but its upstream source was closed for a 0.07–0.28% instruction improvement, and there is no demonstrated end-to-end 1.99 benefit. Reconsider the eight-line nonstandard-macro lint-level gate for the same reason: old upstream rejected the tradeoff, and its historical measurement is not an isolated measurement of the current port.
5. **Treat Clippy module caching as a major removable feature, not an unquestioned default.** It has genuine earlier Ruff gains, but requires transitive audits of 56 passes, driver executable/configuration fingerprints, source-input hooks, platform identity code, and invalidation tests. A current release-profile removal comparison should establish whether the roughly seconds-sized earlier benefit warrants this ongoing cross-repository obligation. It regressed the measured small-crate edit from 52.99 to 60.92 ms.
6. **Prune already-upstream Clippy backports from the PR/history stack.** Seven current PRs are exact zero-file diffs; they introduce no shipped code divergence. Closing/removing these layers simplifies stack management but does not change the binary.
7. **Keep compact artifacts separate from the old Wild performance fork.** The compact reader is a fresh Wild 0.10.0 feature with a different purpose, dependency graph, and measured identity. Its optional bounded payload-cache and external library-manifest experiments should be independently justified or removed, even if core compressed objects are retained.

The implementation is carefully conservative, but that care is itself the cost. [Audited passes](https://github.com/astral-sh/ohm-rust-clippy/blob/f52143702ff1f265014e87d5e6853e70a3b15728/clippy_lints/src/incremental_lints.rs) have to move as complete passes. Helpers must not hide dependency reads in process caches, source-map reads, early AST collectors, or cross-module state. Module mode bypasses one-entry macro memoization and performs inherited MSRV queries that ordinary traversal can avoid. Adding a pass requires transitive auditing and positive/invalidation fixtures for every lint.

[Driver identity](https://github.com/astral-sh/ohm-rust-clippy/blob/f52143702ff1f265014e87d5e6853e70a3b15728/src/incremental/identity.rs) identifies Linux's running executable through `/proc/self/exe`, and manually declares a Darwin libproc region ABI to establish that the executable pathname still names the mapped image. The entire executable is hashed each enabled invocation. Unsupported configurations and compiler capability probes retain whole-crate traversal. [Source helpers](https://github.com/astral-sh/ohm-rust-clippy/blob/f52143702ff1f265014e87d5e6853e70a3b15728/clippy_utils/src/source.rs) add opt-in compiler source-file query reads to snippet construction. These are necessary guards for the feature as implemented; deleting them piecemeal while keeping module caching would be unsafe.

## Wild compact artifacts: distinct unshipped feature

[PR #32](https://github.com/astral-sh/ohm-wild/pull/32) reads `RCOBJ001` compact objects directly, including members of conventional `.rlib` archives. It adds1,304 lines in `compact-artifact/src/lib.rs`,414 in `library.rs`,79 CLI lines,43 `.dwo` helper lines and Wild file-kind/input/section integration. A compact object is not ELF: its eager metadata uses tagged section offsets and independently compressed cold payload blocks. The same crate must coordinate with rustc emission/export/fallback and Cargo lifecycle logic.

This is a **storage architecture change**, not another2% linker optimization. Evaluate it against physical disk saving and complete clean/build/edit/test/Clippy/export/debugger lifecycles, not merely standalone link time. Ohm #140 measurements used Wild `dba82ebe`; current Wild head `9179eb98` has later validation/CI changes and the raw metadata allocation-bound repair. The current PR says24 CI checks pass, but binary identity with the measured artifact has not been checked.

Two separately removable layers deserve skepticism:

- `WILD_COMPACT_CACHE_BYTES` adds file-backed streaming decode, a global logical LRU working set, weak references, eviction/advice bookkeeping and unsafe page-discard advice. Borrowed slices keep their mappings; actual RSS, eager metadata, active reads and OS page cache are not capped. Backing files can approach the full decoded selected payload. This is an opt-in memory/I/O experiment, not needed by default pinned in-memory decode. Retain only with independent pressure measurements proving useful net behavior.
- `RCLIB001` external store manifests keep backward-readable versions1/2, relocation/ancestor-store lookup, separate metadata and content-addressed members, plus `wild-pack` archive/references/inspect/export tooling. Conventional archives containing compact objects provide a potentially simpler format boundary. Removing manifests is feasible only after confirming rustc/Cargo/clean/export no longer consume that representation; the compiler agent owns that dependency decision.

Do not delete decoder validation, section-size checks, metadata bounds or the debug-compression padding/TLS repairs in the name of simplification while retaining compact inputs. These are correctness requirements for the selected format. If abandoning compact formats entirely, delete compiler emit/export, Cargo detection/lifecycle and Wild reader support together, then use released upstream Wild.

[Current checkpoint](https://github.com/astral-sh/ohm-linker/blob/d185a5e6a486353564858fbf4d6d2319defe346f/docs/checkpoint.md) already reaches the appropriate conclusion: native linking occupies too little of these workflows to justify more allocator/hash/cache/PGO work. These observations do not prove a general regression—the session study is small—but they fail to establish benefit for a large independent implementation. It would be wasteful to keep tuning minor passes before proving a workflow where linking dominates.

The current source supports only a subset: native arm64, no LLVM-bitcode-only inputs, thin archives, arm64e/authenticated relocations or LC_LINKER_OPTION autolinking. Its 121 tests and bounded runtime/debugger checks are substantial, but maintaining Apple-linker compatibility is an open-ended task. This compatibility cost exists even if all measured standalone links are15%faster.

## Dependency-aware simplification order

1. Archive unshipped old Wild and both macOS linker implementation stacks with evidence/refs intact. No shipped behavior changes. Do not delete correctness fixes inside an experiment that remains runnable.
2. Drop seven empty Clippy PR layers and other already-upstream historical backport layers; confirm the release source tree is unchanged.
3. Remove independent Clippy #46, then #44 after checking diagnostics with nested lint settings. #38/#41 are independent low-cost candidates and can be evaluated separately.
4. For rustfmt, reconstruct a candidate from the exact upstream base retaining package cache, buffered snapshot I/O, single-pass clean verification and format/check shared identity. Keep existing safe fallbacks. First omit #19 and #18; then compare full #14 removal. Reverting downstream commits in isolation may conflict because their schemas/APIs evolved together; rebuilding a focused stack is cleaner.
5. Compare shipped vs package-only formatting on cold first checks, direct edits, multi-file edits, root edits, writes that need formatting and warm no-ops in actual Ruff/uv/Codex. Report absolute time, not synthetic percent alone. A shorter tool fork can retain major warm wins without all certificates.
6. Compare Clippy whole-crate traversal with current module caching on the actual shipped optimized toolchain. If removed, return every audited pass to ordinary registration, remove module identity/source-tracking integration, then remove compiler hooks only after proving no other external-driver consumer exists. Keep `redundant_clone` prefilter/lazy borrower map independent of module caching.
7. If compact objects survive, use one source of truth for the format. Decide ordinary-archive vs external-store manifests first; remove unused producer/consumer/clean/export modes together. Remove optional bounded decode only with a clear memory-pressure choice. If the entire feature is abandoned, delete compiler/Cargo/Wild integration together and use upstream Wild.

## Coverage and limits

This was a comprehensive **family inventory and architectural review**, not a fresh line-by-line correctness proof of every compiler-adjacent lint and every Mach-O relocation. Exact shipped Clippy/rustfmt diff files and central cache/driver/manifest/parser implementations were inspected. All live tool/linker PR bodies and per-PR file inventories were collected; old Wild representative code paths (CIE cache, section-data cache, packed/frozen/group indexes and page population) were inspected. Both Mach-O implementation trees and benchmark/design/checkpoint documents were inspected, with attention to mode complexity, signatures, ownership and unsupported inputs. Compact format decoding/caching/library/CLI integration was inspected. Tests were read selectively, not executed.

No rebenchmark is required to recommend keeping already-excluded experiments out or pruning exact empty commits. Current release-profile ablations **are** required before claiming that removing Clippy module caching or single-module rustfmt loses no worthwhile benefit. Current shipping benchmark audit observations and any independent devbox measurements belong to the main report; historical evidence here is never presented as a fresh verification.
