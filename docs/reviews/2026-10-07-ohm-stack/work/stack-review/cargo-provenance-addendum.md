# Cargo shared-cache provenance and admission addendum

Reviewed the exact shipped Cargo snapshot `018a2b93409433dc5bc05c5fce838ae69e9bc396` in `/private/tmp/ohm-stack-review/cargo`. This is a source review and PR-evidence audit; no compiler commands, benchmarks, remote commands, or source mutations were performed. References below are pinned to that snapshot. The source snapshot includes production modules and their inline tests; I did not independently inspect every Cargo integration test.

The strongest immediate simplification is to consolidate repeated facts about compiler execution. The shared-artifact namespace and build-to-check diagnostic provenance need separate admission decisions, but they currently repeat enough of the same file, executable, environment and target checks to create unnecessary review and rebase work. This is smaller and more concrete than introducing a general cache framework.

## Boundaries that should stay separate

Shared namespace construction is global and occurs before compiler execution. It includes Cargo/rustdoc/linker/native-tool identities, job count, configuration, bootstrap/version overrides and trust policies ([compilation_files.rs:225–651](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/compiler/build_runner/compilation_files.rs#L225-L651)). Cross-mode provenance additionally binds diagnostics and captures the *actual child process* after build-script overrides ([build_runner/mod.rs:255–283](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/compiler/build_runner/mod.rs#L255-L283), [compiler/mod.rs:1363–1365](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/compiler/mod.rs#L1363-L1365)). Reusing the initial global environment in place of that child capture loses a real correctness boundary. Cargo's synthesized dynamic-library search variable intentionally uses inherited values rather than an apparently forced `[env]` entry; preserve that rule in shared fact collection.

The dependency-graph eligibility check runs before `CompilationFiles` exists and can admit owned workspace libraries under workspace locking. The shared registry closure, by contrast, requires remote immutable packages and memoizes macro/native runtime policy along the actual unit closure. These final eligibility predicates should remain separate. One fact layer is enough; a polymorphic cache-admission framework or one universal eligibility boolean would make the contracts harder to review.

## Narrow admission and flag surface

There are ten explicitly named `ohm_*` controls in [features.rs:961–970](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/workspace/features.rs#L961-L970), plus related embedding/relinking and locking controls. They are not ten independent binary switches: defaults derive several effective choices, linker/trust controls are enums, and shared caching requires fine-grained locking. Do not quantify the test burden as an unconstrained power-of-two count.

The most questionable extra admission tier is native `build-scripts`, between `strict` and `all` ([features.rs:169–186](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/workspace/features.rs#L169-L186)). The documented user workflow chooses `all`; [#82](https://github.com/astral-sh/ohm-cargo/pull/82) explains narrower native tainting but provides no marginal timing or eligible-hit count for the intermediate tier. Ask the implementation to justify this tier with actual use and lost-hit coverage. Removing it alone saves only a few match/parser/test branches, not the authentication or native closure implementation. It is a modest surface cleanup, not a large code-removal claim. Retain a conservative default and an explicit permissive opt-in if broad native reuse remains an intended workflow.

The two trust domains should not be collapsed into one `trust-all` control: macro trust also authorizes local workspace snapshot imports, whereas native trust controls authenticated registry artifacts. Their risks and lifetimes differ. Likewise, the `audited_macro_runtime` and `permissive_native_runtime` recursion states in compilation_files.rs:1571–1634 are needed by the retained policies, rather than arbitrary generic modes that can simply disappear.

The independent Clippy seed override deserves a smaller follow-up: shipped automatic selection already derives from worktree seeding, bundled Clippy and file-clone support (compilation_files.rs:609–642). `Some(true)` bypasses the automatic clone capability selection. If copy-based forced isolation is no longer a supported product path, remove that forced path with its associated behavior and consider deriving isolation entirely from the retained seeding policy. The override also supports useful ablation/debugging, so its existence alone is not evidence to remove isolation. Other strong flag removals follow feature deletion, especially incremental expiry and the focused-test prototype; retaining dead switches after deleting those features would preserve unnecessary states.

Restricting optimized admission to shipped native targets could reduce cross-target policy obligations while preserving ordinary Cargo fallback, but native targets can still be replaced through `RUST_TARGET_PATH`, local target JSON and custom compiler backends. Narrowing eligibility does not make those checks dispensable. Measure current cross-target hit coverage before deciding whether the reduced cache coverage is acceptable; this source audit supplies no evidence that cross-compilation reuse is unused.

## Concurrent miss coalescing

[#96](https://github.com/astral-sh/ohm-cargo/pull/96) is a good marginal ablation candidate: +149/-13 nonvendored source by the parent inventory, and its PR body gives no quantitative end-to-end benefit. Actual eligibility is much narrower than "coalesces shared-cache misses": fine-grained locking, an authenticated shared unit, Build/Check mode, a library that is not a procedural macro, and **zero unit dependencies** ([fingerprint/mod.rs:970–984](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/compiler/fingerprint/mod.rs#L970-L984)). It saves duplicate compilation only when concurrent initially dirty jobs target the same eligible leaf and one finishes while another waits. Sequential warmed workflows and miss-heavy units with dependencies do not receive this benefit.

Retained coalescing requires fingerprint, dep-info, tracked-file, allowed metadata-environment and expected-output validation under the exclusive lock (fingerprint/mod.rs:991–1071). It marks reused results `BuiltChanged`, preserving downstream generation conservatism. Job scheduling remains dirty; only execution switches to `fresh_work` ([job.rs:93–109](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/compiler/job_queue/job.rs#L93-L109)). That last distinction prevents overstating it as a scheduler improvement.

A removal trial must remove the leaf recheck hook and restore ordinary fingerprint invalidation together: current early invalidation is skipped for coalescible units because they invalidate later under their write lock (fingerprint/mod.rs:1254–1263; compiler/mod.rs:435–441). Preserve shared lock ordering and lock lifetimes. Instrument the existing successful-recheck event to count actual reused leaves and compare a controlled concurrent first-build scenario plus representative multi-worktree sessions. Keep it only if avoided leaf rustc calls save meaningful user time. Do not broaden it to dependency-bearing units to make its impact appear larger without independently solving dependency-generation and runtime-input validation.

Recommended order: remove complete weak features and their switches; consolidate identical constants/predicates; unify bounded compiler facts with deliberate cache-version handling; simplify the generic package-authentication API; then ablate miss coalescing and measure admission-tier hit coverage. None of these findings justifies deleting validation from a cache that remains enabled.
