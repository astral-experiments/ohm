# Ohm stack simplification review

Inventory frozen October 5, 2026; ablation findings updated October 7. Reviewed the seven `astral-sh/ohm*` repositories, the exact Ohm 1.99.0-1 release sources, and the material unshipped experiments. The inventory below uses that fixed release snapshot. Cargo #104/#115 have since been removed from the active stack; historical releases remain unchanged. [Current ablation findings](../stack-ablation/results.md) distinguish accepted measurements from held or unmeasured cases.

**Keep the core that avoids dependency rebuilds, reuses executable objects and shares immutable worktree artifacts. Remove later formatter layers, restore upstream query promotion and retire the separate linker experiments.** Cargo #104/#115 are already removed. A small positive result should earn its maintenance cost, especially when a change adds a cache protocol, semantic shortcut or metadata format.

Twenty-three representative-command comparisons have completed their raw-data audits. The results support removing rustfmt #18/#19 while accepting their measured costs, returning to serial query promotion and removing metadata-prefix reuse while accepting its first-edit costs. Removing the const-impl secondary index improves cold Ruff and uv checks, with both pairs agreeing; Codex edits have mixed costs. The line-table comparison supports keeping that deliberate development-profile choice. The Linux compiler allocator comparison supports returning to jemalloc with explicit Ruff costs and lower maximum-child memory. Removing the six-line Clippy MSRV shortcut also has measured costs, accepted for upstream parity. The individual CGU screens favor removing the 26-line caller-local policy with explicit Ruff and uv edit costs, while retaining the 34-line stable merging policy provisionally for Codex edits. The coroutine layout/debug screen supports removing #99/#132 together: 361 net production lines, accepting Codex no-op/Edit 1 costs of 144/433 ms while later edits improve. Formatter PGO has substantial first-format and edit benefits. Clippy PGO, its small clone and macro guards, and resolver caching remain provisional keeps; the smaller two-pair screens establish practical tradeoffs, without statistical significance claims. [All fresh command results and limits](../stack-ablation/results.md).

The broader formatter and compiler-cache removals also have material costs. Package-only formatting removes 2,145 net lines but adds up to 910 ms to the measured dirty-file commands. Removing the compiler worker-cache/retention bundle costs Codex's cold check a paired median 5.97 s; all six pairs are slower. These results justify holding those broad removals while questioning their individual mechanisms. Proc-macro caching and dependency-read filters have mixed workload effects, including repeated losses on some Ruff or Codex edits. [Formatter comparison](../stack-ablation/benchmarks/package-only-results.md), [compiler-cache comparison](../stack-ablation/benchmarks/compiler-cache-bundle-results.md), [proc-macro comparison](../stack-ablation/benchmarks/proc-macro-default-results.md), [read-filter comparison](../stack-ablation/benchmarks/next-fleet-plans-01/ordinary-read-filters-plan-01/read-filter-results.md).

Clippy cache removal triggered a compiler panic on a real Codex edit; [the saved trace and source review](../stack-ablation/benchmarks/clippy-codex-failure-01/source-diagnosis.md) identify Rust #106's serialized-value forwarding as the strongest hypothesis, with individual causation still unproved. Sparse metadata and semantic shortcuts now have complete raw audits. Sparse removal raises maximum-child RSS by roughly 16–60 MiB in several states; that measured memory cost is accepted explicitly in the recommendation below. [Current progress](../stack-ablation/progress.md) records the final disposition of every comparison, including held and unmeasured cases. The [small-patch dispositions](source-dispositions.md) identify another 25 empty frozen commits that can leave the stack without changing source.

This report distinguishes **removal recommendations**, **simplification/ablation candidates**, **features to retain provisionally**, and **experiments to hold or archive**. These are maintenance judgments informed by the measurements; they are not claims that every proposed removal is behavior-neutral or loses zero performance. Fresh screens use the [representative command matrix](../stack-ablation/benchmarks/representative-command-matrix.md), reporting each cold/no-op/edit state without executing project tests. Native validation retains each variant’s recorded scope. The combined removal implementation has not been built or timed. Clippy retains the original `--all-targets`/`--tests` lint recipes; those targets are compiled and linted without executing the project test suite.

## What should remain in the smaller stack

The proposed core has meaningful independent or workflow evidence, despite its own complexity.

| Core | Evidence | Retention boundary |
| --- | --- | --- |
| Public API hashes and dependency cutoff | Current uv factorial ablation saves 3.008 s / 42.40%. API-preserving dependency check/Clippy/test examples save many seconds. | Keep semantic hash correctness, exported generic identity, metadata/link generation distinction and dependency validation. The favorable private-edit workload is not every edit. |
| Cached relinking and retained executable objects | Large indirect-edit build/test gains; compiler support is comparatively small and Cargo owns replay. | Keep `.rlink` object lifetime, transitive link generation and metadata-ready scheduling. Avoid keeping unrelated LLVM temporaries or putting objects in crate-search paths. |
| Shared immutable dependencies and build-to-check reuse | Bundled build-then-check savings 46.56 s uv / 61.86 s Codex; worktree registry examples save seconds. | Keep authenticated source/driver/native-input boundaries, cached diagnostics and deadlock repairs. Consolidate duplicated facts; require marginal hit coverage for further eligibility tiers. |
| Clone-only worktree seeds and bundled Clippy isolation | Controlled macOS first-worktree + build 23.95→3.59 s; APFS Clippy/fork workflow 27.044→23.595 s and 12.75% less allocation. | Keep source relocation and build-script rerun/result validation. Keep clone-only policy; byte-copy fallback caused large regressions. Accept and retest ~15 ms donor no-op Clippy overhead. |
| A simpler incremental formatter | Warm Codex no-op 11.911→0.308 s and direct edit 12.437→0.503 s for the bundled tool. | Retain package-level skipping, buffered I/O, shared format/check identity and avoidance of self-imposed second verification. Later layer benefit needs separate proof; first-format regressions matter. |
| Artifact growth repairs | Compiler superseded-session and unpacked-debug fixes bound persistent state growth. | Keep these distinct from optional age-based Cargo expiry. No wall-time win is required to fix unbounded growth. |
| Upstream release optimizations and cheap defaults | Compiler PGO/BOLT, existing Cargo/rustdoc PGO and parallel frontend largely use upstream machinery. | Preserve optimized-build comparability. Two lines enabling an upstream feature are a different maintenance cost from a new persistent cache. Reconsider behavior defaults separately. |

The supplied global instructions explicitly use seeded worktrees and permissive macro/native-tool trust. This is evidence of an intended workflow, not proof of every policy's marginal performance. Keep that workflow provisionally while measuring which admission extensions actually help. Macro expansion caching, registry macro artifact reuse and local-macro worktree imports are three distinct things and should not be conflated.

## What the benchmark evidence does and does not establish

Fresh ablations time representative Cargo commands on pinned Ruff/ty, uv and Codex sources. Compiler checks and library builds each use five command states: cold, warm no-op and one command after each of three recorded edits. The edits are sequential; the compiler recipes do not include a revert. Codex Edit 1 adds transcript-layout bookkeeping, Edit 2 implements stable active-cell rendering with snapshots, and Edit 3 invalidates cached layouts when active cells are removed. [Corrected BUILD labels and preserved originals](../stack-ablation/benchmarks/representative-build-report-label-erratum-01/build-human-label-audit-and-erratum.json) document the presentation correction; measurements are unchanged. Clippy uses cold, no-op, direct-edit and dependency-edit commands; formatting records its relevant edit and fallback paths. These are selected targets, with zero timed project test executions. Library builds exercise code generation without final executable linking; uv's test-only third edit can be inactive for the selected library target.

Each arm starts with private target/shared histories. The earlier campaigns use six counterbalanced pairs per project; the later screens use two. Installation, optimized compiler builds, source preparation, native correctness and training are recorded separately from command timing. Whole pairs affected by unrelated activity are retained and excluded, then retried in their fixed slot with fresh histories. Removing a feature can be slower: the detailed tables preserve every command state, paired range and slower-pair count. Maximum-child RSS is a per-process measure, not total concurrent memory. Paired differences are calculated before taking the median; subtracting arm medians can give a different number. Two-pair screens show practical tradeoffs with limited precision.

The published release study improves the three measured sessions from 1,328.10 to 869.14 seconds, or 34.56%, with two repetitions per toolchain/project. That is material evidence for Ohm's overall value, but does not independently defend each included feature. APFS disk reductions are also substantial, with one/two/ten worktrees: roughly 40–50% for Ruff and 35–58% for uv. Those cohorts combine debug policy, shared storage, seeding and compiler format changes.

The most useful published factorial experiment toggles public API hashing and proc-macro expansion caching within the same release. API hashing saves 42.40% in that favorable parser-edit workflow. Proc-macro caching saves 2.72% averaged over the API settings; with API hashes on, the median difference is 0.123 seconds / 2.96%, but the two same-repetition differences have opposite signs and much larger variation. **This is weak precision for a small gain.** The expansion cache implementation is entirely upstream Rust 1.99; changing its automatic Cargo default does not delete compiler fork code. It also does not automatically justify deleting registry macro artifact reuse or local seed admission.

Two earlier eight-pair proc-macro campaigns were attempted on `charlie-openai-2`, with exact release binary/source hashes, independent warm histories and unchanged contamination guards. Both passed preflight and later encountered unrelated Cargo/rustc activity. Both campaign receipts failed acceptance. There is **no accepted complete comparison from those attempts**, and the partial cells are retained as exploratory evidence without a speedup claim. Generated targets and private worktrees were cleaned after source/ownership/process checks; original artifacts and toolchains were preserved. Details, hashes, receipts and raw packets are in the benchmark appendix; the current ordinary-command scope is recorded in [ablation progress](../stack-ablation/progress.md).

Several confounders materially affect retention decisions:

- **Debug policy:** Ohm's line-table default differs from stock full development debug information. The published uv stock-versus-Ohm comparison includes this default difference; Ruff and Codex use matching explicit debug settings. Some impressive coroutine/span results use full debug and weaken under the current line-table default. Retain/revert profile choices deliberately and compare like profiles when pricing a compiler feature.
- **Shipping optimizer:** Many compiler experiments use stage-one/stage-two unprofiled binaries; current release uses PGO, plus BOLT on Linux. Compiler CodSpeed runs one frontend thread, excludes dependencies from leaf replays and covers mostly registry fixtures. bitmaps-heavy gains are not representative eight-job session savings.
- **Trust and history:** The published replay uses macro trust `all`; the disk study also uses native-tool trust `all`. Warmup is excluded, and some cells have only one observation. These are configured warm development workflows, not all users or cold machines.
- **Absolute effect:** A 15% reduction in an isolated millisecond helper may disappear in total check/test time. Conversely, a 1–2% change in a minute-long session can matter. Report seconds, allocation and memory alongside percent.
- **Negative cases:** The published uv direct check is 3.474→3.714 s (+6.91%); cold uv check is +2.59% with one observation. Its first-format Ruff/uv commands regress about 20–22% (historical Ruff about 32%), while prewarmed Codex formatting wins dramatically. Both phases belong in the formatter decision.
- **Independence:** Separate PR improvements cannot be added. Bundled release-to-release differences do not isolate one feature, and comparing a stale PR base to a rebased head can include upstream changes.

The recommended removals accept several measured losses. They reduce fork protocols and maintenance obligations; the retained features have larger command benefits, required correctness roles or bounded implementations.

## A concrete simplification sequence

1. **Build the source inventory around exact upstream trees.** Stop replaying empty backports and restore incidental `f32`/`f64` formatting. Retain one feature layer per real change rather than historical/superseded alternatives.
2. **Implement the supported removals together.** Cargo expiry and indexed scheduling are already removed. Remove rustfmt #18/#19, parallel query promotion, metadata-prefix reuse, sparse metadata, the const-impl secondary index, the coroutine layout/debug family and the Clippy MSRV shortcut; accept their reported formatting, first-edit, memory and storage costs. Preserve the useful validation for surviving features and archive feature-specific evidence.
3. **Restore ordinary semantic paths.** Remove the coherent #84/#110/#117 shortcuts, accepting their measured state-specific costs. Preserve useful upstream correctness regression cases. Keep #118's separate small dependency-read filter provisionally.
4. **Simplify useful Cargo code.** Share opaque execution facts, logger names, backend checks and environment casing predicates. Separate generic authenticated package identity from macro policy. Preserve distinct pre-execution namespace facts and post-build-script child diagnostic provenance; a universal cache framework would add complexity.
5. **Retain material measured benefits and keep held removals explicit.** Hold the mono family removal after rejected Codex timing; the library scope does not price #65’s test-specific extension. Retain stable CGU merging provisionally; remove caller-local placement with its measured Ruff/uv costs explicit. Keep the broad compiler-cache bundle and package-only formatter replacement on hold because their complete comparisons show material losses. Clippy module-cache removal remains held after the real compiler panic; resolve its correctness failure before considering adoption.
6. **Validate the combined implementation when the removals are made.** Run broad correctness once for that combined variant and reuse the representative Ruff/ty, uv and Codex commands to check cold, no-op and edit costs. Individual marginal results cannot be added into a predicted combined speedup. This follow-up is distinct from the present per-candidate report; macOS-specific changes need an appropriate host.
7. **Keep allocator and optimizer decisions separate.** Preserve compiler PGO/BOLT and the substantial measured formatter PGO benefit; keep Clippy PGO provisionally. Return Linux rustc to jemalloc with its documented Ruff costs and memory reductions. That comparison cannot settle Cargo-only macOS allocation. Accept the historical 17–29 ms Cargo cost if removing that separate macOS integration; fresh optimized Mac timing remains unavailable.
8. **Retire unshipped experiments from active maintenance.** Preserve refs, final evidence and reproducibility instructions; remove ongoing release/CI overlays for held branches. Continue early metadata only as a separate measured research direction if desired.

Validate the combined removals as one implementation. The separate ablations establish tradeoffs for each treatment, but cannot predict the combined result.

### Why the expensive candidates deserve removal or a deliberate ablation

#### Sparse metadata: a modest end-to-end storage change, with new protocol obligations

The sparse table patch adds an occupancy bitmap, rank entries, alternate dense/sparse discriminant, per-access popcount/rank address reconstruction, arithmetic/layout validation, and prefix relocation support. The final hardened production family is +185/-41. Prefix reuse means an invalid table cannot merely be ignored; its encoded byte range must be safely validated before copying to a new metadata file. [Table encoder/decoder](https://github.com/astral-sh/ohm-rust/blob/348339ddae4288ebb3af97d204b19479fef8f5f2/compiler/rustc_metadata/src/rmeta/table.rs).

The final published 1.84–2.64% complete target allocation reductions are the numbers relevant to a disk-space justification. The much larger individual `.rmeta` reduction is not a target-size reduction. Encoding/decoding instruction costs increase slightly on all four measured real crates. The pinned repository's `results/sparse-metadata/README.md` explicitly preserves **original prototype** measurements and warns not to attribute them to the hardened implementation. Current shipping evidence is a separate immutable commit linked from the PR body; archive both evidence sets independently of deciding the feature.

Recommendation: revert sparse production encoding/decoding and its specific relocation checks at the next metadata/compiler-identity boundary. Accept the measured per-process memory increases and historical storage cost explicitly; the original format is simpler to maintain. Preserve public API hashing and validation needed by surviving metadata reuse. A wire-format change requires independently rebuilt compiler/std/cache identity; avoid a mixed-reader transition. Moving archival evidence out of compiler source is a separate simplification.

#### Associated type/const shortcuts: semantic debt disproportionate to narrow gains

`closed_associated_type_bounds_hold` introduces a new cached query, explicit disallowed type flags, a whitelist of scalar/tuple/array well-formedness, local dummy inference contexts, binder/conditional-const/next-solver exclusions, trait-only positive predicates, and region-unconditional-success requirements. A second path replaces associated projections directly when every bound has a restricted shape. [Proof and substitution paths](https://github.com/astral-sh/ohm-rust/blob/348339ddae4288ebb3af97d204b19479fef8f5f2/compiler/rustc_hir_analysis/src/check/compare_impl_item.rs#L2470).

The original proof cache missed required errors when an associated type's own `where Self: Bound` varied between impls with the same definition; the final source has explicit guards and regressions. This is evidence of a maintenance obligation, **not a claim the current compiler still has that bug**. Broad UI/solver/incremental tests are necessary but do not make the custom proof rule maintenance-free. #117's current published benefit is largely bitmaps and only 1.06% across 22 cases, including 1.4% slowdown in one case.

`build_literal_const` similarly creates and validates a special miniature MIR/typeck path for an integer literal `usize`, bypassing ordinary THIR/general MIR building and guarding instrumentation, parent structure, attributes, taint, types, and adjustments. The support is +182/-2 across five compiler files. Its strongest named improvement is bitmaps, not broad projects. [Miniature MIR path](https://github.com/astral-sh/ohm-rust/blob/348339ddae4288ebb3af97d204b19479fef8f5f2/compiler/rustc_mir_build/src/builder/mod.rs#L113).

Recommendation: remove those bespoke semantic shortcuts before simple allocation/slice optimizations. If retained, require a same-release source ablation on Ruff/ty, uv, Codex, rust-analyzer and the full UI/incremental diagnostic corpus. Upstream adoption would transfer maintenance of semantic rules to their owning compiler teams; an indefinitely maintained Ohm-only cache is a different proposition.

#### Serialized query generations and metadata prefixes: cache correctness is the feature's cost

#106 avoids decode/re-encode by preserving old cache bytes at absolute offsets, recursively decoding up to three cache footers, forwarding query indices, sharing allocation state through `Arc` alias chains, and compacting every third generation. The whole old serialized buffer is copied into an owned `Vec` before the old mmap closes. This is not merely a cheap memoization guard: memory footprint, disk write amplification, delayed allocations, hygiene, corruption fallback, and compaction all become part of the cache contract. [Generation structure and copying](https://github.com/astral-sh/ohm-rust/blob/348339ddae4288ebb3af97d204b19479fef8f5f2/compiler/rustc_middle/src/query/on_disk_cache.rs#L52).

Its historical 12-profile uv result measures an unchanged reuse/compaction cycle, not a representative edited command. The wall-time claim is cumulative over prior PRs; the marginal 22-case comparison is not significant. The fresh coherent #83/#88/#106/#107 removal now costs Codex cold library checks a paired median 5.97 s, with all six pairs slower and a +0.64 to +11.53 s range. **Hold that broad removal and retain the family provisionally.** Warm and edited effects are mixed, and the comparison does not isolate generation retention or resolve the separate Clippy cached-value panic. #105's saved-query index remains with serial ordinary promotion; no additional generation-cycle campaign is scheduled. [Accepted command results and scope](../stack-ablation/benchmarks/compiler-cache-bundle-results.md).

#57 adds a 351-line manifest module plus encoder admission/relocation logic, checksums, protected source spans, definition span hashing, source-map layout, atomic inode replacement, retained work products, and compatibility fallback. It is coupled to public API hashes and exact source positions, not merely reachable metadata. [Manifest protocol](https://github.com/astral-sh/ohm-rust/blob/348339ddae4288ebb3af97d204b19479fef8f5f2/compiler/rustc_metadata/src/rmeta/encoder/metadata_prefix.rs), [prefix admission](https://github.com/astral-sh/ohm-rust/blob/348339ddae4288ebb3af97d204b19479fef8f5f2/compiler/rustc_metadata/src/rmeta/encoder.rs#L3255). The fresh six-pair screen supports **removing prefix reuse coherently**, accepting its Ruff/uv first-edit costs of 295/643 ms, with both pairs slower. Codex no-op and second edit improve 132/211 ms; ten of fifteen ranges cross zero. Remove the producer/consumer protocol and work-product state together, preserving complete metadata reuse, public hashes and validation needed by surviving features. [Every accepted state](../stack-ablation/benchmarks/next-fleet-plans-01/ordinary-prefix-plan-01/metadata-prefix-results.md).

#### Worker caches: do not infer the value of seven caches from three-cache measurements

#83 introduced three 16,384-entry worker arrays for types, predicates and generic argument lists. Later #88/#107 add a type-list cache plus supertrait, clause-instantiation and function-signature caches and a worker-local freshening hash map. The final shipped interner therefore has **seven fixed arrays per worker**, not the originally measured three. Every cache hit checks a full key and uses canonical results, which is a useful safety property. Nonetheless, per-worker memory, code layout and repeated branch/key checks remain ongoing costs. [Final cache definitions](https://github.com/astral-sh/ohm-rust/blob/348339ddae4288ebb3af97d204b19479fef8f5f2/compiler/rustc_middle/src/ty/context.rs#L132), [freshening cache](https://github.com/astral-sh/ohm-rust/blob/348339ddae4288ebb3af97d204b19479fef8f5f2/compiler/rustc_infer/src/infer/freshen.rs#L167).

The completed matched-PGO/BOLT comparison removes the coherent worker-cache/serialized-query family, preserving separately useful local restructuring. Its 18 pairs and 180 ordinary eight-job library checks support **holding the broad removal**: Codex cold checks lose 5.97 s in every pair, while warm/edit effects are mixed and no Ruff/uv state has a range wholly on one side of zero. The family result does not price individual arrays, freshening maps or inline-layout changes. Initial bitmaps/syn instruction savings likewise cannot establish each member's value. Keep the shared interner's separate "find before reserve" simplification; no additional split timing campaign is scheduled. [Every accepted state and memory scope](../stack-ablation/benchmarks/compiler-cache-bundle-results.md).

Preserve compatibility only for formats already shipped/adopted, not every research prototype. [Compact compiler diff](https://github.com/astral-sh/ohm-rust/pull/157/files), [early metadata sequencing](https://github.com/astral-sh/ohm-rust/pull/156/files).

### Removal ordering and validation boundary

1. **Pure churn/bookkeeping:** restore formatting-only upstream changes, collapse empty PR layers, move frozen benchmark evidence out of compiler production tree.
2. **Clear tradeoffs:** remove/defer #123 sparse encoding; prune #84/#85 tiny wins and #66 parallel promotion; archive #145 and #128; avoid merging #136/#137/#138 without relevant whole-workflow gain.
3. **Semantic shortcuts:** remove the measured coherent #84/#110/#117 family and const-impl secondary index. Accept the reported state-specific costs. Keep #118's separate small read filter provisionally and preserve useful upstream regression coverage.
4. **Follow the measured family decisions:** remove prefix reuse and the coherent coroutine layout/debug family with their losses explicit; hold the worker-cache/retention bundle and mono reuse. Preserve core public hashing, link freshness and the retained Clippy source/driver invalidation contract. Any combined removal implementation needs its own correctness validation.
5. **Retained feature contracts:** only then retune Cargo automatic defaults. Rust flags false by default may still be automatically enabled by Ohm Cargo; compiler default false is not proof that released users do not pay the feature cost.

For removal, do not delete tests merely to shrink the line count while keeping their feature. Necessary suites include public hashes and transitive reexports/generic sharing, incremental hash verification across many generations, source whitespace and diagnostic-span Clippy tests, async-drop/custom MIR/codegen/debugger tests, and linked program output after missing/mutated cache artifacts. Conversely, retiring a feature should retire its feature-specific tests/docs/options/protocol fields as a unit. Count real compiler invocations and actual cache admissions; object reuse/internal query counts alone are mechanisms, not user-visible speedups.

This source review covered the shipped diff, family implementations and material current experiments. It is not an exhaustive proof of compiler semantic equivalence, a security audit, a newly built toolchain validation, or new measurements of every patch. Most published percentages are older or non-PGO compiler results; the comprehensive coordinator report should explicitly separate those from newly collected exact-release devbox evidence. No heavyweight compiler builds or remote jobs were performed by this review agent.

## Appendix B: Cargo and release review

Review date: October 5, 2026. This is a recommendation report; no production sources were changed.

The main opportunity in Cargo is to reduce the number of independent cache protocols. Public API cutoff and shared immutable dependencies have useful evidence; incremental expiry, the scheduler replacement, and several optional experiments have much weaker cases. Remove features as complete units rather than deleting the validation that makes retained caches correct.

### Recommendations

#### Remove the optional incremental configuration expiry feature

[Cargo #104](https://github.com/astral-sh/ohm-cargo/pull/104) is disabled by default. Its controlled experiment assigned three configurations artificial ages of 40 days, reclaimed 221.37 MiB of 349.42 MiB of logical incremental state, and preserved 97 finished artifacts. It does not demonstrate how often configurations really become stale, physical APFS savings, or a net benefit over ordinary cleaning. The next parser edit cost 0.903 seconds after expiry versus 0.244 seconds with the state retained.

The shipped implementation adds a 617-line module, new clean CLI behavior, changes to incremental directory selection and usage tracking, marker versions, ownership checks, hourly refresh logic, profile locking, and interrupted-deletion recovery. There are 777 lines of expiry integration tests and another 283 lines of reuse tests. The initial and hardening commits add +790/-119 in nonvendored source before later interactions. See [incremental_gc.rs](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/workspace/incremental_gc.rs).

My judgment: remove this whole feature from the shipped Cargo stack. Preserve its report and experiment branch. Rust's separate superseded-session cleanup is a different feature and should not be removed with it. If expiry returns, require observed long-running disk pressure and a policy benchmark that includes the cost of rebuilding expired data.

#### Revert the dependency scheduler replacement

[Cargo #115](https://github.com/astral-sh/ohm-cargo/pull/115) replaces the upstream queue with dense indices, per-artifact counters, a binary heap, an iterative dependency walk and sparse transitive-reachability bitmaps. Its single file change is +322/-139; it adds a second representation of graph identity and changes equal-priority tie breaking.

The best recorded whole-Cargo instruction reductions are 0.27% for an unchanged Ruff check and 0.66% for an unchanged uv check. Neither invokes the compiler. Native elapsed no-op, edit and revert measurements are inconclusive and order-sensitive, and these Cargo binaries lacked release Cargo PGO. Compiler BOLT is irrelevant to these no-compiler commands. See [dependency_queue.rs](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/util/dependency_queue.rs).

My judgment: the measured gain is too small for a wholesale replacement of upstream scheduling in this project. Revert to the upstream queue and preserve any tests that expose real upstream correctness gaps. No special benchmark is necessary to say the present evidence is insufficient; a future proposal should show a repeated representative session benefit, including concurrent builds.

#### Question the separate Cargo allocator fork

[Cargo #106](https://github.com/astral-sh/ohm-cargo/pull/106) has better independent evidence than the scheduler: matched PGO builds on an Apple M5 Max improve metadata and unchanged commands by 4.6–8.3%, including Ruff check 216→199 ms and uv build 296→267 ms. Linux did not establish a win and used more memory, so Cargo uses mimalloc only on Apple Silicon.

Its custom integration is small (+37/-1 outside vendored source), but it adds another copy of mimalloc 3.5.1, a CMake dependency and a bespoke native allocator build. That is 26,598 vendored lines, additional to the compiler's allocator source. The PR explains that the chosen Rust dependency bundled the older allocator, so blindly replacing this with that dependency would change the tested implementation.

My judgment: remove the Cargo-specific allocator integration. Its historical 17–29 ms warm-command savings are too small for the duplicate native vendor/build ownership under this simplification goal. The prepared removal passed independent source review: three integration files change by +1/-47, all 54 vendor files are deleted, the optional CMake dependency and orphan lock entry disappear, and the other optimizations retain their empty ohm-defaults feature gate. Fresh matched optimized Mac timing remains unavailable; no new performance result is claimed. Linux compiler mimalloc is separate. See [prepared source patch](../stack-ablation/cargo106/remove-macos-mimalloc.patch).

#### Keep resolver reuse, but retain a narrow contract

[Cargo #66](https://github.com/astral-sh/ohm-cargo/pull/66) is +279/-11 source initially, with execution-setting-key refinement [#88](https://github.com/astral-sh/ohm-cargo/pull/88) adding +61/-1. The final dedicated cache file is 237 lines. It fingerprints all relevant manifests, the lockfile, Cargo/compiler identity, resolver modes, configuration and relevant environment, stores an atomic digest, and reuses the earlier complete workspace resolution. It still resolves selected package features.

The historical original [#16](https://github.com/astral-sh/ohm-cargo/pull/16) reports graph reuse alone reducing warmed Codex metadata 413→358 ms and Nextest 961→824 ms, with actual dependency-edit check/Clippy/Nextest reductions of 125/218/246 ms. These measurements predate the current compiler/Cargo base; they are evidence for the feature, not current-head estimates.

Provisionally keep this bounded optimization. The fresh six-pair screen finds that removal costs Ruff first edit 1.09 s and two uv edits 0.51–0.55 s, with both pairs slower. Cold uv/Codex and Ruff no-op favor removal; other states vary. That mixed result supports the existing contract, with two-pair precision limits, and does not justify extending it into a daemon, persisted executable plan or second lockfile representation. The cache still recomputes manifest fingerprints across invocations. [Every command state and range](../stack-ablation/benchmarks/resolver-cache-results.md), [resolve_cache.rs](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/ops/resolve_cache.rs).

#### Simplify shared-cache provenance by sharing facts, not weakening policies

Shared registry caching and build-to-check reuse own a substantial part of the Cargo fork. The initial implementations add +2,267/-40 and +1,285/-13 nonvendored source respectively. Active-graph eligibility adds +1,223/-102. Procedural macro and native-tool policies, compiler provenance and cache admission add further hundreds of lines. The final changed files include +2,390/-7 in `compilation_files.rs`, +1,356/-11 in `build_runner/mod.rs`, +1,290/-2 in `unit_dependencies.rs` and +1,980/-107 in fingerprints; these totals also include other features.

The user-visible evidence is materially stronger than for many micro-optimizations: the latest complete release's build-then-check examples save roughly 46.56 seconds for uv and 61.86 seconds for Codex, and cross-worktree registry reuse saves seconds. Those examples combine multiple mechanisms; they do not isolate every extension to eligibility.

There are multiple compiler-driver identity implementations and related executable, loader, codegen-backend, environment and toolchain checks across:

- [compilation_files.rs](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/compiler/build_runner/compilation_files.rs)

My judgment: keep the basic shared cache and build-to-check reuse, and consolidate common low-level facts into one bounded provenance implementation. Keep separate decisions about registry sharing, cross-mode reuse and seed eligibility, because their contracts differ. This is a focused refactor candidate, not a reason to introduce an all-purpose cache framework. A second simplification option is to reduce the set of admitted macro/native-tool cases and let excluded cases use ordinary Cargo behavior; measure loss of actual cache hit coverage before choosing it.

Do not remove deadlock repairs, exact bundled-Wild recognition, compiler identity checks, lock lifetimes, diagnostic replay, native-input boundaries or fingerprint validation independently. They support correctness of retained optimizations.

#### Keep the clone-only worktree design, with a higher bar for further admission features

[Cargo #101](https://github.com/astral-sh/ohm-cargo/pull/101) introduces source checksum relocation, import staging, build-script reruns and output verification, private snapshots and a Git worktree CLI. Its initial source change is +1,479/-30. The final main worktree module is 628 lines and script-result revalidation is 272 lines; source and fingerprint hooks live elsewhere.

The original controlled local macOS comparison, with warm registry artifacts and permissive macro/native trust, measured worktree creation plus first build 23.95→3.59 seconds unchanged and 25.08→8.33 seconds with an edit. The latest release's APFS disk figures have sizable bundled savings across worktrees. This is a meaningful Ohm use case, although the controlled timing only has two samples per arm and includes the compiler relocation change.

[Cargo #126](https://github.com/astral-sh/ohm-cargo/pull/126) simplifies import policy by requiring copy-on-write cloning and eliminating the byte-copy fallback and override. Keep that policy: earlier byte-copying measurements added 15 seconds for Ruff forks and 44–59 seconds for uv. Ordinary I/O errors still need to surface; unsupported cloning is a seed miss. The independently checked clone probe is part of ensuring the feature really works, not removable test-only machinery.

[Cargo #108](https://github.com/astral-sh/ohm-cargo/pull/108) isolates bundled Clippy state so subsequent worktrees can retain build/test seeds. Its APFS workflow shows 27.044→23.595 seconds and 984.916→859.350 MiB of final allocation, with four samples per arm. Repeated donor Clippy costs about 14.95 ms more, or 16.66%, and three of four pairs are slower. This supports keeping the feature for the measured worktree workflow, while explicitly accepting a short-command cost. It is not evidence for a Linux byte-copy speedup.

My judgment: keep worktree seeds and Clippy isolation together as a coherent feature. Stop adding separate import modes. Local-macro trust [#103](https://github.com/astral-sh/ohm-cargo/pull/103) deserves separate scrutiny: it lowers APFS allocation and compiler invocations in a local pilot, but does not establish general elapsed benefit and expands the correctness contract. The supplied global instructions explicitly select macro/native-tool trust and worktree seeding, so this review treats that as an intentional workflow, rather than assuming the policy is unused. Keep it provisionally and measure its marginal value. If it is removed, remove its entire policy surface; do not weaken validation of remaining imports.

### Removal and validation order

1. Restore purely incidental upstream formatting and stop replaying empty backports. No runtime benchmark needed.
2. Remove Cargo expiry as a whole, including its CLI, flags, directory-selection/tracking hooks, legacy-marker tests and feature-specific CI. Verify ordinary Cargo clean and existing worktree/shared-cache tests still pass.
3. Upstream scheduling has been restored; no new standalone scheduler timing gate is required. Keep artifact-specific readiness and upstream behavior.
4. Remove compiler/tool micro-features with weak marginal evidence in separate reviewable changes; compare the final lean stack using the existing representative command matrix rather than rebenchmark every seven-line change independently.
5. Consolidate provenance facts only after dead branches are gone. Retain all behavior-focused rejection/rebuild tests needed by the remaining caches.
6. Retain the measured formatter PGO and provisional Clippy PGO benefits, preserving upstream optimization. Remove the separate Cargo-only macOS allocator integration on its source/historical maintenance judgment, accepting the historical 17–29 ms command cost; fresh optimized Mac timing is unavailable. The Linux rustc allocator screen is a distinct configuration comparison and cannot supply that missing Mac result.
7. Preserve the upstream-Wild option and clone-only seeds; do not package Wild-fork, Mach-O, resident-query or compact-format experiments as part of this simplification.

### Boundaries that should stay separate

Shared namespace construction is global and occurs before compiler execution. It includes Cargo/rustdoc/linker/native-tool identities, job count, configuration, bootstrap/version overrides and trust policies ([compilation_files.rs:225–651](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/compiler/build_runner/compilation_files.rs#L225-L651)). Cross-mode provenance additionally binds diagnostics and captures the *actual child process* after build-script overrides ([build_runner/mod.rs:255–283](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/compiler/build_runner/mod.rs#L255-L283), [compiler/mod.rs:1363–1365](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/compiler/mod.rs#L1363-L1365)). Reusing the initial global environment in place of that child capture loses a real correctness boundary. Cargo's synthesized dynamic-library search variable intentionally uses inherited values rather than an apparently forced `[env]` entry; preserve that rule in shared fact collection.

The dependency-graph eligibility check runs before `CompilationFiles` exists and can admit owned workspace libraries under workspace locking. The shared registry closure, by contrast, requires remote immutable packages and memoizes macro/native runtime policy along the actual unit closure. These final eligibility predicates should remain separate. One fact layer is enough; a polymorphic cache-admission framework or one universal eligibility boolean would make the contracts harder to review.

### Narrow admission and flag surface

There are ten explicitly named `ohm_*` controls in [features.rs:961–970](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/workspace/features.rs#L961-L970), plus related embedding/relinking and locking controls. They are not ten independent binary switches: defaults derive several effective choices, linker/trust controls are enums, and shared caching requires fine-grained locking. Do not quantify the test burden as an unconstrained power-of-two count.

The most questionable extra admission tier is native `build-scripts`, between `strict` and `all` ([features.rs:169–186](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/workspace/features.rs#L169-L186)). The documented user workflow chooses `all`; [#82](https://github.com/astral-sh/ohm-cargo/pull/82) explains narrower native tainting but provides no marginal timing or eligible-hit count for the intermediate tier. Ask the implementation to justify this tier with actual use and lost-hit coverage. Removing it alone saves only a few match/parser/test branches, not the authentication or native closure implementation. It is a modest surface cleanup, not a large code-removal claim. Retain a conservative default and an explicit permissive opt-in if broad native reuse remains an intended workflow.

The two trust domains should not be collapsed into one `trust-all` control: macro trust also authorizes local workspace snapshot imports, whereas native trust controls authenticated registry artifacts. Their risks and lifetimes differ. Likewise, the `audited_macro_runtime` and `permissive_native_runtime` recursion states in compilation_files.rs:1571–1634 are needed by the retained policies, rather than arbitrary generic modes that can simply disappear.

The independent Clippy seed override deserves a smaller follow-up: shipped automatic selection already derives from worktree seeding, bundled Clippy and file-clone support (compilation_files.rs:609–642). `Some(true)` bypasses the automatic clone capability selection. If copy-based forced isolation is no longer a supported product path, remove that forced path with its associated behavior and consider deriving isolation entirely from the retained seeding policy. The override also supports useful ablation/debugging, so its existence alone is not evidence to remove isolation. Other strong flag removals follow feature deletion, especially incremental expiry and the focused-test prototype; retaining dead switches after deleting those features would preserve unnecessary states.

Restricting optimized admission to shipped native targets could reduce cross-target policy obligations while preserving ordinary Cargo fallback, but native targets can still be replaced through `RUST_TARGET_PATH`, local target JSON and custom compiler backends. Narrowing eligibility does not make those checks dispensable. Measure current cross-target hit coverage before deciding whether the reduced cache coverage is acceptable; this source audit supplies no evidence that cross-compilation reuse is unused.

### Concurrent miss coalescing

[#96](https://github.com/astral-sh/ohm-cargo/pull/96) is a good marginal ablation candidate: +149/-13 nonvendored source by the parent inventory, and its PR body gives no quantitative end-to-end benefit. Actual eligibility is much narrower than "coalesces shared-cache misses": fine-grained locking, an authenticated shared unit, Build/Check mode, a library that is not a procedural macro, and **zero unit dependencies** ([fingerprint/mod.rs:970–984](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/compiler/fingerprint/mod.rs#L970-L984)). It saves duplicate compilation only when concurrent initially dirty jobs target the same eligible leaf and one finishes while another waits. Sequential warmed workflows and miss-heavy units with dependencies do not receive this benefit.

Retained coalescing requires fingerprint, dep-info, tracked-file, allowed metadata-environment and expected-output validation under the exclusive lock (fingerprint/mod.rs:991–1071). It marks reused results `BuiltChanged`, preserving downstream generation conservatism. Job scheduling remains dirty; only execution switches to `fresh_work` ([job.rs:93–109](https://github.com/astral-sh/ohm-cargo/blob/018a2b93409433dc5bc05c5fce838ae69e9bc396/src/compiler/job_queue/job.rs#L93-L109)). That last distinction prevents overstating it as a scheduler improvement.

A removal must remove the leaf recheck hook and restore ordinary fingerprint invalidation together: current early invalidation is skipped for coalescible units because they invalidate later under their write lock (fingerprint/mod.rs:1254–1263; compiler/mod.rs:435–441). Preserve shared lock ordering and lock lifetimes. The completed source audit and natural uv concurrency probes find every eligible immutable unit reserved before freshness observation, with stale preflight re-prepared under exclusive leases; each arm compiles the real leaf once. Both arms also agree on the 69 shared-cache cases (66 passes and the same three known failures) and all 33 worktree cases. Recommend removal without a repeated latency campaign for surrounding unaffected work. The callback may still execute redundantly; this does not prove a universal invocation count or zero cost. Do not broaden eligibility or force a race to manufacture an effect. [Accepted source/native evidence](../stack-ablation/cargo96/native-raw-01/independent-review.json), [corrected Cargo trace](../stack-ablation/cargo96/native-cargo-log-02/independent-review.json).

Recommended order: remove complete weak features and their switches, including miss coalescing; consolidate identical constants/predicates; unify bounded compiler facts with deliberate cache-version handling; simplify the generic package-authentication API. Any later admission-tier coverage study is conditional on a remaining policy question. None of these findings justifies deleting validation from a cache that remains enabled.

2. **Do not introduce the old Wild optimization fork.** Most steps have small memory/instruction improvements with inconclusive latency effects. 3. **Remove rustfmt multi-leaf batching, accepting its measured command costs, and challenge the whole per-module certificate layer.** Fresh real-project ablation shows that removal costs 131.4 ms in Ruff and 50.0 ms in uv when four already-formatted leaf files change, with all six pairs agreeing; warm no-op effects are negligible. 7. **Keep compact artifacts separate from the old Wild performance fork.** The compact reader is a fresh Wild 0.10.0 feature with a different purpose, dependency graph, and measured identity. [Audited passes](https://github.com/astral-sh/ohm-rust-clippy/blob/f52143702ff1f265014e87d5e6853e70a3b15728/clippy_lints/src/incremental_lints.rs) have to move as complete passes. Helpers must not hide dependency reads in process caches, source-map reads, early AST collectors, or cross-module state. Module mode bypasses one-entry macro memoization and performs inherited MSRV queries that ordinary traversal can avoid. Adding a pass requires transitive auditing and positive/invalidation fixtures for every lint.

### Wild compact artifacts: distinct unshipped feature

[PR #32](https://github.com/astral-sh/ohm-wild/pull/32) reads `RCOBJ001` compact objects directly, including members of conventional `.rlib` archives. It adds1,304 lines in `compact-artifact/src/lib.rs`,414 in `library.rs`,79 CLI lines,43 `.dwo` helper lines and Wild file-kind/input/section integration. A compact object is not ELF: its eager metadata uses tagged section offsets and independently compressed cold payload blocks. The same crate must coordinate with rustc emission/export/fallback and Cargo lifecycle logic.

This is a **storage architecture change**, not another2% linker optimization. Evaluate it against physical disk saving and complete clean/build/edit/test/Clippy/export/debugger lifecycles, not merely standalone link time. Ohm #140 measurements used Wild `dba82ebe`; current Wild head `9179eb98` has later validation/CI changes and the raw metadata allocation-bound repair. The current PR says24 CI checks pass, but binary identity with the measured artifact has not been checked.

Two separately removable layers deserve skepticism:

- `WILD_COMPACT_CACHE_BYTES` adds file-backed streaming decode, a global logical LRU working set, weak references, eviction/advice bookkeeping and unsafe page-discard advice. Borrowed slices keep their mappings; actual RSS, eager metadata, active reads and OS page cache are not capped. Backing files can approach the full decoded selected payload. This is an opt-in memory/I/O experiment, not needed by default pinned in-memory decode. Retain only with independent pressure measurements proving useful net behavior.
- `RCLIB001` external store manifests keep backward-readable versions1/2, relocation/ancestor-store lookup, separate metadata and content-addressed members, plus `wild-pack` archive/references/inspect/export tooling. Conventional archives containing compact objects provide a potentially simpler format boundary. Removing manifests is feasible only after confirming rustc/Cargo/clean/export no longer consume that representation; the compiler agent owns that dependency decision.

Do not delete decoder validation, section-size checks, metadata bounds or the debug-compression padding/TLS repairs in the name of simplification while retaining compact inputs. These are correctness requirements for the selected format. If abandoning compact formats entirely, delete compiler emit/export, Cargo detection/lifecycle and Wild reader support together, then use released upstream Wild.

No-op command improvements are often only tens or hundreds of milliseconds: uv check 22 ms, Codex check 107 ms, Clippy 144/102 ms, and tests 193/113 ms. ### Evidence limits and smallest useful followups

Compiler CodSpeed's [current local methodology](../../external/ohm-rust/src/tools/codspeed/README.md) replays leaf compiler invocations with dependencies excluded, one frontend thread, full incremental hash verification, and a stage-1 compiler without release PGO/BOLT. The 22-case suite emphasizes four registry fixtures (five cases each) plus two real-crate checks. This is useful compiler engineering evidence, but small gains dominated by a fixture such as bitmaps are weak grounds for retaining semantic specialization in a parallel released development stack.

The published release comparison has good provenance and contamination controls: exact source/tools, balanced order, matching profiles/commands/test-start counts, pinned compatibility patches, no detected unrelated compilers,30-second preflight, and continuous host telemetry. Managed Falcon/service overhead remains in timings. These controls improve credibility; they do not create independent evidence for each optimization.

Coverage gaps that matter for simplification decisions:

- The published release study uses one 16-CPU EPYC host for Linux timing; physical disk is measured on one Apple M5/APFS system. No Windows benchmark, memory-pressure/concurrent-link benchmark, filesystem matrix, or broad single-thread versus parallel/frontend tradeoff.
- Released PGO/BOLT compiler differs from most component experiments' unprofiled stage1/2 compilers. Code-layout, allocator and optimizer interactions can erase or alter small historical gains.
- uv stock Full debug versus Ohm line tables is a real bundled default difference. All ablation cells use the same Ohm default, so that matrix is fair; stock-versus-Ohm uv totals do not isolate compiler reuse from debug policy.
- Published session runs opt into proc-macro trust=all; APFS study additionally native-tool trust=all. They measure a configured development workflow beyond packaged defaults. Strict-trust worktree value and cache failure/fallback frequency remain unmeasured.
