# GNU AArch64 Ruff AST rebuilds

[Held-out measurements and simultaneous intervals](RESULTS.md) · [Standalone native and instruction replay](REPLAY.md)

The workload is an ordinary cross-built Ruff library on an x86-64 Linux host. It applies the complete 74-file Ruff commit `ef23c9c39eb3029bab0139c3ea7ae6d95c4131e0` to its direct parent and builds `ruff_python_ast` for `aarch64-unknown-linux-gnu`. Every role uses the same compiled Cargo reader, Cargo defaults, 118 common SDK files and matched build options. The only changed SDK member is the host rustc driver. Each actual editable AST invocation receives incremental compilation, `-C lto=off` and `-Zohm-check-relink-inputs`. None requests a branch cache.

The raw observer labels V as M. All three roles use the aware Cargo `c18e91b514b2c4e4966c9ab03232c804af3e1b57`. Earlier studies used a different Rust M, earlier Cargo readers, and disjoint inputs. Their observations never contribute to these estimates.

This Cargo builds on #293 and its #292 GNU linker fallback. The signed -20 package instead contained Rust `7e71d315` and Cargo `2d44bd4a` from #294, which implements a separate shortcut for declared native inputs. We measured no paired GNU speedup against that shipped SDK. The signed Cargo was an old-reader compatibility control for V. A separate measurement of the signed compiler used unchanged work on the Darwin cross target and omitted Cargo instructions. A release that combines the new reader with #294 needs its own integrated native-provider and migration tests and a fresh performance comparison. In a separate signed-rustc Ruff unicode_names2 control, shipped #294 reported zero dirty units on both unchanged runs. Both #293 and the new reader recompiled its host build script and unicode_names2 each time. The generated source files were byte-identical. That independent workload was outside the AST instruction cohort. The proposed reader needs integration on the release lineage to retain its existing behavior. The source relationships and exact endpoints are in `source/cargo-lineage.json`. The counter measures the host Cargo and every rustc child, including their user-space threads. It rejects any new uncounted process in a measured command. It excludes the kernel and Rustup dispatch. GNU GCC, collect2, GNU ld and QEMU run in separately recorded correctness controls. Instruction ratios describe the host work to build the rlib. The study has no native AArch64 latency or linked-executable speed endpoint, and no new build-cache policy or storage-size benchmark.

The AST compiler itself instantiates `compact_str::repr::ensure_read`. Its own .rlib and .rmeta dependency rules on A and N contain the hard marker, both before and after the edit. On V they contain the versioned recheck marker. The .d file's own inputs exclude the synthetic marker in each role. A separate source-matched diagnostic replay identifies both local assembly calls inside the AST unit's imported `CompactString::push_str` function at line 939 of compact_str 0.10.0. In each original pilot, the actual edited AST rustc profiles contain 95 LLVM codegen calls on A, 95 on N, and one on V. The existing incremental mechanism can reuse the other units after V proves the crate's assembly is file-free. A separate generic per-CGU optimization reaches some of the same work; its gains cannot be added to these results. See `native/ast-local-root.json` and `pilot/codegen.json`.

The v2 marker is deliberately missing. Signed -20 Cargo and the unmodified #293 reader treat it as an ordinary missing dependency and compile conservatively. The aware reader recognizes the synthetic compiler-output rule, validates the encoded dep-info and leaves final native linking enabled. Real higher-priority, missing, malformed and same-inode/restamped provider changes were compared to independently empty AArch64 consumers, including on unchanged Rust. There are 444 native Cargo provider/migration commands, 12 genuine named-path collision commands and 58 separate compiler checks. The unversioned experimental compiler had earlier accepted undeclared external native changes on the signed Cargo. The versioned companion protocol was qualified separately before instruction enrollment. Run `python3 -IB provider-safety/verify.py` for the complete results. A separate reader reopened all six provider archives and checked 192 retained rustc depfiles. The binary or rlib/rmeta output rules ended in the expected marker, and the depfile’s own rule contained only ordinary inputs. The standalone marker also matched. The reader rejected two deliberate corruptions per archive. The raw hashes and per-phase results are in `native/all-provider-textual-rules.json`.
