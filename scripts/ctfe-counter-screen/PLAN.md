# Repair a real Ruff parser error with and without a checkout switch

Run 41285793847 on two independent Linux boots found that restoring a deliberately invalid parser after a branch return took about 115 billion user instructions with the candidate and 74 billion with its parent. The intervening AST comment edit saved about 109 billion. This study asks whether the extra repair cost also occurs on a checkout that never switches. It is a diagnostic of those two histories. It cannot establish an unconditional performance gain or independently count rustc or linker processes.

Both compiler installations, Cargo, stock Wild, opts, fixed file paths and Ruff revisions must match the earlier study. Build the actual 375-unit CLI using `cargo +ohm build -p ruff --bin ruff --locked --offline -j4 --message-format=json` with branch caching enabled. Establish baseline A, B and comment-edited B with separate empty target and build roots for each compiler. Execute the seven-command historical branch-return sequence, including its repeated build, invalid parser and repair. Then use independently empty roots to build only B on Y, change the same one byte of the AST comment, repeat the build, introduce the same parser type error, and restore the parser. Git HEAD and its branch ref must have identical device, inode, ctime, mtime and bytes across all five single-checkout commands. Each successful warm executable and its external typed client must match independently empty builds. Require E0308 at the edited site and the correct repair. Keep original output and storage receipts for every visit.

Counterbalance compiler order on two fresh hosts and exclude the four earlier scored or structural boots. Keep every ordinary clock with at least 99.5% scheduling, and all 30 visits per host. For each history independently, compare candidate versus parent instructions on the repair. Classify a material cost if both fresh hosts use at least 10% more instructions. Report an observed upper bound of 5% in this pair if neither host uses more than 5% extra. Other results are inconclusive. Publish raw counts for every command, including the complete seven-command and five-command totals. Count allocated storage across both roots once per inode. This diagnostic alone is insufficient to submit or release the candidate.
