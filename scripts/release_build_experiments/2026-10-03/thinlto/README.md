# Incremental ThinLTO dependency object reuse

This experiment compares one optimized local compiler with `-Zohm-thin-lto-dependency-cache=no` and `yes`. Both variants explicitly use release ThinLTO and incremental compilation. A separate fat-LTO build uses each repository's ordinary release profile. This change targets repeated optimized builds after source edits; it cannot reuse dependency objects on a clean first build. The candidate remains opt-in; the measurements do not establish performance of the distributed PGO-trained Ohm compiler.

The tested compiler source is `ed3bc629d5b3ecf16a362fa61c451aa65c82b2b7`, based on `348339ddae4288ebb3af97d204b19479fef8f5f2`. Its driver SHA-256 is `1427a333ad710c07e51c36d4ef297f48024750afc49edd8b832c91898cb4e4e7`. Cargo is the released Ohm 1.99.0-1 component, commit `018a2b93409433dc5bc05c5fce838ae69e9bc396`. The compiler reports an unknown Git hash because of bootstrap provenance; the source-file manifest, applied-diff hash, and binary hashes identify the tested candidate.

[Compiler draft 155](https://github.com/astral-sh/ohm-rust/pull/155) is now at `108208fcf94e95bb716dd99b1fc4505c3c05bdfb`. Its only change from the measured commit wraps two test fixture literals to satisfy tidy. `ci-tidy-provenance.json` verifies identical compiler tree and blob IDs, identical decoded fixture bytes, and equivalent test tokens. No compiler change or benchmark rerun followed that formatting fix.

Four counterbalanced incremental ThinLTO entrypoint-edit pairs give a **14.82%** geometric-mean wall-time reduction for uv and **2.97%** for Ruff. All eight pairs passed the predeclared acceptance rule. Ruff is a small, mixed result: its fourth pair regressed by 3.78%. The first rebuild has the largest gain for both tools; the later-three sensitivity is 12.00% for uv and 1.47% for Ruff. The first pairs remain in the headline.

The strict runtime audit passes all 240 timed captures. The medians above are descriptive. Paired geometric-mean time changes for reuse on/off are −0.49% for uv Jupyter (95% paired bootstrap interval −3.03% to +2.01%), +1.26% for uv Trio (−0.35% to +3.04%), −1.54% for Ruff check (−3.68% to +0.29%), and +0.36% for Ruff format (−0.66% to +1.29%). Every interval includes zero, so these guards do not establish a cache-option runtime change. They are not a general runtime verdict.

Profile choice has a clearer runtime tradeoff: on/fat paired geometric means are +5.74% for uv Jupyter (95% interval +4.21% to +7.37%) and +5.45% for uv Trio (+3.65% to +7.22%). `runtime-analysis.json` retains all 20 ratios for every comparison. `compute-runtime-geomeans.py` reproduces the analysis using 20,000 resamples of 20 complete paired log ratios, restarting `random.Random(0)` for each comparison. It exponentiates each resampled log mean, sorts the results, and takes zero-based indices 500 and 19499 without interpolation. The separate direct-rustc mechanism check reuses all 7,221 dependency modules on both invocations, compiling zero dependency modules and preserving the executable's hash.

Primary edit samples observe 0.09–0.64 outside CPU cores on the 16-CPU host, with no sampled outside compiler. Peak individual child RSS ranges are 2,495,396–2,882,116 KiB off versus 2,040,796–2,688,176 KiB on for uv, and 1,587,040–1,597,736 KiB off versus 1,583,436–1,621,620 KiB on for Ruff. The host is an AMD EPYC-Milan VM with CPU affinity and effective cpuset 0–15. The measured harness could not read root `cpu.max` or `memory.max`, so per-service limits are unverified; it does not establish unlimited quotas. Sampled available memory never fell below 41,315,696 KiB and sampled swap use was zero.

Workloads are uv `46b84fd0bfec23b72f29e8e2185ba68a65052f48` (`-p uv --bin uv`) and Ruff `1df6db3e463ffa1b587dcf47f25360d40389b0f7` (`-p ruff --bin ruff`). Every timed build uses `--release --locked --verbose`, warm downloaded dependencies, normal Cargo concurrency, and separate bounded target directories. Rust compiler logging is disabled during timing. Entrypoint edits insert a different `std::hint::black_box(Nu8)` call for every pair, so the root binary must compile on every timed edit. This is a favorable reuse case. One library body edit per CLI is reported separately as directional evidence.

The final cohort runs on a Linux x86_64 devbox with 16 CPUs. Primary entry-edit measurements use the original launcher environment; the separate library-edit and runtime phases use the controlled launcher described below. Before each build, the harness requires five seconds with at least 95% CPU idle and no other compiler. It accepts the first two complete off/on pairs and two on/off pairs without observed outside compiler activity and with mean outside CPU at most 5% of machine capacity. Whole rejected pairs remain in the raw data. A one-second process sampler records outside CPU, memory, swap, and pressure. Very short-lived processes between observations can escape sampling. Peak RSS is the maximum individual child-process RSS returned by `wait4`, not aggregate process-tree memory.

All earlier 32-CPU-host cohorts are excluded. One initial implementation lacked the combined-index hash guard, one enabled verbose compiler tracing, and one deep-cloned the work-product map per codegen worker. The final Arc implementation was then moved off that host when unrelated validation work resumed. These diagnostic samples are retained with explicit reasons; they are not pooled with the final cohort.

The focused run-make test and seven existing incremental ThinLTO tests pass on the source and compiler identified above. They cover changed bodies, export reachability, missing cached objects, option changes, unchanged importers of changed dependencies, continued reuse after invalidation, hashless bitcode, and byte-identical executables after a direct compiler cache hit. A separate untimed trace establishes dependency reuse on the real uv workload.

Runtime guards use binaries restored to identical original sources, with 20 counterbalanced iterations for each workload. uv resolves the pinned repository's `jupyter.in` and `trio.in` offline after warming one public PyPI cache, with `--exclude-newer 2026-10-01T00:00:00Z --python-version 3.12`. Ruff checks all CPython v3.12.7 at `0b05ead877f909b7efe712db758012d9dbece7ce`; its formatter checks `Lib` while excluding `**/test/**,**/tests/**` fixtures. Output hashes and exit statuses must match. The separate post hoc audit compares raw stdout, stderr, and exit statuses across all 60 captures per workload. For uv, stdout is checked independently of the output-file hash, and exactly one anchored resolver-duration line is normalized; every other stderr byte stays in order. For Ruff check, the full warning-line multiset is enumerated in the audit receipt and must match before its order is normalized; all other stderr bytes keep their positions. Formatter stderr must be empty, and only `Would reformat:` path-line order is normalized; footer and other stdout lines keep their positions. The current formatter emits rich diff diagnostics: all 275,250 lines compare byte-for-byte, with no `Would reformat:` path lines to normalize. The receipt records their count/hash and the exact footer. Raw captures are retained unchanged.

The harness requires Linux, Python 3.11 or newer, and Rustup. To reproduce, prepare clean uv and Ruff worktrees at the listed commits, a complete candidate sysroot including the pinned Cargo, and warm the public Cargo cache at `/tmp/codex-cargo-home`. Then run `./reproduce.sh --workspace <worktrees> --toolchain <sysroot> --targets <empty-target-root> --output <empty-output-directory>`. Add `--runtime` after extracting the pinned CPython archive beneath `<worktrees>/corpus`. The launcher uses system Python with environment-based path overrides and site hooks disabled, preventing inherited development-environment import hooks from replacing the trusted helper. The helper creates an `ohm` alias only inside an isolated `RUSTUP_HOME` in the workspace. It does not replace the user's global toolchain alias.

Hashes attached to raw timing JSON, compiler logs, correctness execution records, and the raw archive describe the original captured bytes. The compact publishable JSON and Markdown are formatted separately; any publication manifest hashes are computed after formatting. Measured Python harness bytes are preserved unchanged.

The raw archive stores each unique file once, indexed by its SHA-256, with a path, size, and digest for every original capture. Remote originals remain intact. Run `python3 restore-raw-evidence.py raw-evidence.tar.gz raw-evidence-manifest.json <empty-directory>` to restore the original paths and bytes, checking the archive, index, and individual file digests. Duplicate files are reconstructed as hardlinks. The strict runtime auditor reads those original captures and does not rerun the binaries.

The main timed build cohorts completed before an inherited Python import hook broke the follow-up helper import. Only previously unrun phases were resumed using the controlled system-Python launcher. The launcher receipt records the verified helper path and frozen script hashes. The remote heredoc added one trailing newline to each original local Python script; the published measured scripts preserve those actual remote bytes. No completed build timing was rerun or replaced.
