# Predeclared held-out #329 native test-build pilot

The source pair and Ruff commits are recorded in the factory registration. The ordinary command is `cargo +ohm test -p ty_server --test e2e --no-run --locked --offline -j4 --message-format=json`. The only experimental treatment is the reviewed #329 patch applied to the signed -23 compiler source. Both compiled SDKs use the same signed Cargo and Wild. Installation, package download, test execution, input inspection and archiving occur outside the hardware windows. No procedural-macro or native-tool trust overrides are set.

One fresh Linux x86-64 host executes P,C,C,P. Each visit starts with empty build and target directories, and uses the same canonical source, SDK, Cargo home and output paths. It runs cold OLD, the actual Old→New edit (primary), first unchanged, deliberately invalid Rust, repair, an independent kernel exec census of a reversed and re-edited history, and an independently empty NEW build. An invalid macro, changed target roster, missing body, inconsistent source read, partial/multiplexed complete-command PMU or incorrect native verdict prevents a performance claim. The kernel census is off-clock. Attribution to a particular process requires positive clock time for its positive counts and the same named object-retention subset as the ordinary edit.

Each successful Cargo invocation must expose the original 289 package/target/feature entries, the unchanged 200 e2e test names and the genuine debug_command verdict. The OLD ELF must fail on the updated snapshot, while the NEW executable must pass. The warm, repaired and empty NEW executable must match in full within each role, and OLD and NEW full native executables must match across arms and orders. The fresh and incrementally updated ty_ide rlibs must contain identical native object bodies. A direct external Rust consumer must see the new Project method after the edit and an E0599 on OLD. The same workflow must diagnose E0308 immediately and recover after repair.

In addition to primary inherited retired-user instructions, retain cold and first-unchanged counts, actual by-process census, exact native bodies in both Ruff states, per-object identity and full incremental-storage observations. The parent and candidate OLD/edit graphs and work-product tables for the first pair are retained for attribution. No benefit will be claimed from equal object bytes alone. A six-independent-boot confirmation is worth considering only if both mirrored primary pairs improve by at least 2% and retain additional verified physical donors. No order/sample will be discarded for being unfavorable.
