# Wild 0.11.0 on the signed Ruff #29697 e2e link

The signed compiler creates the exact native symbol-table input in its temporary directory. It serializes the object, writes those bytes to `symbols.o`, and passes that filename to the linker. The stable capture point is the serialized byte buffer or the kernel file opened by the loader. This is an ordinary file in the Wild input list. It disappears when the owning compilation returns. [Signed Rust source](https://github.com/astral-experiments/ohm-rust/blob/d57fd1515986dccecdcece8da85e651bfb4b81f9/compiler/rustc_codegen_ssa/src/back/link.rs#L2628-L2633)

A library lookup iterates directories, then candidate filenames in the search mode’s order. It stops at the first successful file-type request. Requests inherited from a linker script can begin at the script directory. The production Makefile dependencies are derived later from successfully loaded filenames. Wild's `--trace` prints loaded filenames, and `--dependency-file` deduplicates those filenames and omits inputs the loader classified as temporary. Neither call receives the preceding unsuccessful candidate requests. A future certificate would need each source request and search mode, ordered negative results, the selected presently opened generation and exact bytes, and recursively reopened script choices. Separately it must bind the compile-time native symbol operand, selected linker + options, and unchanged output, and handle mutation/replacement before publishing the fresh outcome. Rechecking stored positives cannot establish the preceding negative search sequence.
