# Unscored crate-root codegen partition pilot

The compilers differ in one partition rule on top of the source-matched signed Ohm −23 port of [Rust #329](https://github.com/astral-experiments/ohm-rust/pull/329). The input is the normal optimized dev library build. Ruff is the historical checkout at each revision.

~~~sh
cargo +ohm build -p ty_ide --lib --locked --offline -j4 --message-format=json
~~~

One fresh x86_64 Linux worker runs both compilers on each revision pair. Ruff #29697 runs P then C, while #29604 runs C then P. The first case adds a public project method. Its native client tests an old-method error and resolves both settings of the script selector and three vendored paths. The separate body-only change was selected before reading held-out placement or timings. Its private-body edit preserves the Salsa revision after an unrelated file write. The client links the actual ty_project, ty_ide, ruff_db and Salsa from each build, reads the public revision on both sides of the event and checks a public ty_ide path conversion.

The frozen selector (residual/eligibility/owner-rule.json, SHA-256 76796738dc5c9b6801e114d0d32be466e9acf053251937549432db34bff31e92) runs after ordinary oversized-CGU splitting. In the original 245-unit ty_project, it chose the unsplit crate root and its volatile root. Eleven spare slots give four lanes each. The original compiler routine places every reachable private inline copy. The candidate has its own incremental format. Each role starts with empty target and build directories and the same signed Cargo/linker. The hardware run includes codegen work in dependencies, cold builds and the whole changed build.

The primary metric for discovery is user instructions inherited across the entire ordinary edited Cargo process. We also collect per-thread, per-program hardware counts on separate kernel-observed ordinary repeats, requiring the same Cargo roster, warm named native outputs and positive running-time counters for the affected ty_project compiler. Both roles run a fully empty NEW. Each archive member and symbol-index row is joined against its saved incremental object. Two no-ops are checked. A genuine E0308 must disappear on repair. Whole OLD and NEW client ELFs, the consumed archives, full metadata and independently generated native bodies are retained. Edited, repaired and empty NEW programs must be byte-identical within each compiler. Public definition identities and edit memberships must agree across the two source compilers. Warm and empty builds have existing metadata-fingerprint drift. Every decoded warm-to-empty added, removed and changed key set must agree across the two compilers. The existing six-boot parent control observed 3,084 differing public rows, nine expansions and 26 required crates in ty_ide, and 4,276, 46 and 25 in ty_project. See [the original matched metadata study](../evidence-29697-six/README.md). The earlier complete OLD client must reproduce its original, distinguishable answer after switching the filesystem to NEW.

Record the cold and edited whole-process counts and full artifact-tree file/byte costs. Reopen the original serialized partitions for both compilers and count actual total CGU memberships and MIR estimates, including repeated inline copies and the complete target. Compare emitted bodies and the original versus regenerated donor roster on both edits. The prospective target is a 20% reduction in the affected compiler on the original edit. A single hardware pair per edit is diagnostic. Any positive goes back to the current shipping base for independent replication before a draft.

The compiler source revisions are 5c5af1a053326e6ce5df048c4dcb30b53e01a069 and 3b376385fc19bf9fb979baba742540eb8ab27c60. Existing work covers size balancing (#115), source module and caller-local assignment (#59), bounded oversized splits (#179/#183), and stable CGU merges (#60). This prototype considers the two default crate roots after the existing splitter has consumed its slots.

The local archive reader needs Python 3.11+ and zstd. It authenticates original native query bytes, matches the actual saved object set to the serialized mono-item partition record, and counts the eight predicted new WIPs in the discovery target.

~~~sh
python3 -IB partition_outcome.py --case 29697 original-29697.zip --output reviewed-29697.json
python3 -IB partition_outcome.py --case 29604 original-29604.zip --output reviewed-29604.json
~~~
