# Linux musl v2 marker and native provider qualification

This is an unscored, independent source-qualification guard. The existing #285 parent run has its own declared-directory and global-asm control. Neither mechanism occurs in the positive rlib here. No candidate compiler, hosted Cargo run, or timing was acquired by the local offline packet check.

## Invocation

Use an x86-64 Linux host with ordinary rustup, strace supporting per-thread timestamps and decoded file descriptors, b3sum, musl-gcc, GNU ar and readelf. Supply the existing 183-member host+musl kit from the #285 job, the new source-qualified C driver, and the three enrolled Cargo executables. The two rustc launchers must give the same entire verbose version using the same regular launcher. The host uses its actual configured musl target linker. The prior #285 build used cc, collect2 and GNU ld. The previously enrolled static libc/CRT remain installed throughout. [Parent workflow](https://github.com/astral-experiments/ohm/actions/runs/41166655409)

Fill out subjects.example.json with the real paths and the independently qualified C SHA-256. Each role's source and bytes are checked, along with both Cargo/rustc proxy resolutions and the actual loaded driver. If the QA Git transplant has another parent revision, bind its compiler-tree equivalence to the reviewed Rust commits in the enclosing source receipt. The hash for P in the example comes from the 183-member parent kit. Keep all input images and the fresh work area on the same filesystem. Only the private SDK view changes when swapping roles. The regular frontend and selected images get private hard-link aliases. Such aliases keep bytes, inode and mtime but change the original files' link count and ctime. The other SDK members are exposed by read-only use of symlinks. Run against the supplied task-owned image files.

The following is the whole six-history panel. ROOT must already exist, be empty, and be on that filesystem. Each private work and output path must be new and contain no whitespace or colons. Only one arm runs at a time. The workspaces have no network dependencies. Verifier JSON, complete compressed strace streams, both stdout and stderr, ELF bodies, both kinds of dep-info, and source/inode receipts are kept under the requested output.

```sh
set -eu
STUDY=/path/to/this/packet
ROOT=/absolute/new/empty/qualification-root
MANIFEST=/absolute/filled-subjects.json
python3 -IB "$STUDY/selftest.py"
for layout in private shared; do
    python3 -IB "$STUDY/guard.py" --subjects "$MANIFEST" --work "$ROOT/$layout-mechanism" --out "$ROOT/$layout-mechanism-evidence" --layout "$layout" --suite mechanism
    for reader in signed strict; do
        python3 -IB "$STUDY/guard.py" --subjects "$MANIFEST" --work "$ROOT/$layout-$reader" --out "$ROOT/$layout-$reader-evidence" --layout "$layout" --suite migration --legacy "$reader"
    done
done
```

Each configuration invokes the real rustup proxy, an ordinary debug build and a fixed target, with no compiler wrapper, linker override, profile override, trusted build-script option, or extra Rust flags. The shared variant enables just Cargo's documented shared-registry-cache policy. The application and producer remain workspace members. An encoded record in the private target under shared policy stays labeled private. This panel makes no claim that these workspace packages became immutable registry packages. A signature-qualified public SDK installation and a same-version source-built C/P driver are distinct roles. The enclosing QA must supply and authenticate the source products.

## Admission

* The only positive producer uses the two exact scalar register comments, imposed on the nonconstant return value of an actual external C function. The static declaration specifies `-bundle`. The Rust consumer only returns the provider's value as its process exit code. The build script outputs two search directories and one `rerun-if-changed=build.rs`. The entire raw script output, Cargo JSON paths, unchanged hashes/physical identities of all Rust sources and absence of a new build-script process are checked.
* On the C + #301 settled path, the producer must be Cargo-fresh with zero physical producer rustcs, a physical v2 depfile, no v1/hard or synthetic self-input, and an authenticated indexed LNK1 v2 in its actual Cargo dep-info. The binary has no synthetically marked inputs of its own. Every visit requires a physical full or cached downstream Rust compiler and exactly one actual target linker with the expected `-o`. A consumer-only stock linker with no real provider open cannot pass. The admitted path is the returned file descriptor of the selected archive from the linker's process or one of its worker descendants. Physical compiler processes must have opened the enrolled driver. The absent high provider generates a negative high lookup before selection of the low one.
* Distinct stages check the original 17, a new high provider 29, same-inode/size/mtime contents 47, malformed bytes twice, repair to 29 and removal back to 17. Each warm state has a fresh same-absolute-path build with both target and build roots empty, the same source, compiler and external archives. Successful static-musl ELFs must match in full SHA-256 and actual exit. Malformed inputs must return Cargo 101, identify the archive, and make the actual linker or bundled rlib producer fail at its correct stage. Directory creation or source timestamp changes cannot satisfy the mechanism gate.
* On the parent, the actual producer must still run full rustc and emit its hard marker. With both comment expressions removed from an otherwise identical C producer, the settled build must do zero compiler or link work. The separate bundled and unrecognized-opcode C fixtures require the full producer. For the bundled case the producer itself must open the correct archive and must reject malformed bytes before the consumer/linker runs. In the unbundled cases no producer may open the candidate native archive; that read belongs to the downstream linker.
* Each legacy reader first produces raw v2 with no authenticated trailer, then repeats with full rustc. Upgrade to #301, insert or replace a provider, require a genuinely fresh producer with LNK1 on the settled visit, then physically downgrade Cargo while leaving the same C driver at the same path. The old Cargo must open the active, SHA-identified v2-encoded record, through its own process or thread, before any rewrite, reject the malformed high provider after a real producer/consumer rebuild, repair, and upgrade again. All successful visits have an independent clean oracle. A fresh namespace or an inactive record lookup is reported as an unsuccessful direct-read gate even if behavior matched. Finally P and C drivers are swapped under the identical complete rustc -vV. If a P visit legitimately reuses C's existing v2, it must reopen the exact retained record without recompiling the producer, relink, and match the independently empty P ELF. A full P compilation must emit hard.
* Each visit preserves the raw trace before classification. `refused.json` records the first failed assertion and the completed frontier. The absence of `complete.json`, or a child's nonzero exit, is an unqualified history. The six independent commands may be run as separate fail-independent QA jobs when partial diagnoses are desired. No score or downstream release conclusion follows from the offline parser checks.
