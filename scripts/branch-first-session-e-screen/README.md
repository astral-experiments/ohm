# Ruff first-checkout feasibility screen

Two new Linux workers run Eoff/Kon/Eon and its reverse at the same absolute SDK, Ruff source, target and build paths. `PLAN.md` fixes both real source histories and the storage and instruction thresholds. `inputs/e-source.json` and `inputs/source-replay.json` must contain the independently reopened source job and its matching native certificate before the workflow will accept an enrollment. E is Rust `c9a6a212d38d778ed0e9d2c7057a9dedb179fff2`, a direct child of K `0afbeff303d3658bff52582d8f1a996d59e6c8ce`. The original K SDK, strict Cargo and stock Wild are hash-pinned in `../branch-return-pmu/source-kit.json`.

The source locator from job 41227867294 validates the capsule before checking all four mixed-compiler receipts, but returns the last case hash in its `manifest` field. `source_media.py` checks that exact historical value against the original `K-packed-A-to-E` receipt and independently recovers the actual capsule digest by comparing the full manifest with the job terminal in the second official archive. The new reader then restores all 81 SDK files with that digest. Both original identifiers remain in `inputs/source-replay.json`.

The suite has three independently empty clean references per arm. These include the real original A and B, and the old parser behavior from Ruff #28233 committed on the same A branch. Every successful visit requires Cargo’s complete 375-unit inventory, its real Ruff/AST outputs and the exact executable bytes from an empty build on the same SDK. The bad edit must produce the actual `E0308` from `ruff_python_parser`. The ordinary Unicode provider cases exercise changed, same-stat and malformed native inputs outside every counter window. A one-bit change in either source-input archive, invalid kernel counter, missing ELF or missing/truncated table payload refuses the corresponding result.

The worker writes these artifacts independently on each host.

| Location | Contents |
| --- | --- |

A settled target is the union of actual `(device, inode)` allocations across both roots. `metrics.evaluate()` accepts 33 independently admitted per-host rows (three arms, seven original and four same-branch phases) and computes raw directions and preregistered margins. An endpoint allocation and the largest sampled file-system usage answer different questions. Only a successful complete pair on distinct new boots can be used to evaluate the feasibility thresholds. The official originals and independent native and source readbacks guard that admission.

To exercise the source history, storage and numerical guards locally, use a read-only Ruff repo and the two originals from the prior storage-only qualification. No compiler or new PMU result is involved.

python3 -IB scripts/branch-first-session-e-screen/test_screen.py \
