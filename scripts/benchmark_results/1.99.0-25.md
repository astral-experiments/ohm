# Ohm 1.99.0-25 on Linux

## Published toolchain

The table shows mean elapsed time on Linux across two replays per toolchain for Ruff, uv, and Codex, and four for ty. The total sums the four means before rounding.

| Session           | Rust 1.99.0 | Ohm 1.99.0-25 | Time saved |
| ----------------- | ----------: | ------------: | ---------: |
| Ruff              |    402.95 s |      223.08 s |     44.64% |
| uv                |    132.78 s |       79.92 s |     39.81% |
| Codex             |    503.97 s |      276.04 s |     45.23% |
| ty                |    276.67 s |      174.16 s |     37.05% |
| All four sessions |  1,316.38 s |      753.21 s |     42.78% |

The median of five warm runs fell from 13.89 s with stock Rust to 1.78 s with Ohm (7.80×). Both toolchains passed the same 207 examples and ignored the same nine. ## Slower replay steps

One step in the Ruff, uv, and Codex replays took at least 0.75 s longer with Ohm. Times are means of two runs per toolchain.

| Project | Replay step                                                             | Stock Rust |     Ohm |
| ------- | ----------------------------------------------------------------------- | ---------: | ------: |
| Codex   | Recheck the exact custom-height regression after integrating the widget |    32.84 s | 36.56 s |

[All replay steps and both timings](https://github.com/astral-experiments/ohm/blob/976d690ab83ceabf39649112c06da8e662357152/scripts/benchmark_results/sessions.json)

The first Codex replay stopped when unrelated processes used 6.07% of CPU, above the 5% limit. A second attempt stopped because the first attempt’s audit file still occupied the output path. We excluded one stock sample from each attempt. A later CPU spike occurred after the first pair had finished timing. We kept that pair and used a fresh idle check before timing the second.
