# Correctness and provenance

The candidate keeps compact objects in ordinary, self-contained `ar` archives with raw embedded metadata. Cargo's `-Zohm-compact-artifacts=yes` is explicitly opt-in and selects the matching bundled Wild on native `x86_64-unknown-linux-gnu`. Ordinary consumers and exported static libraries receive materialized ELF objects. The external-store manifest prototype remains a comparison mode; its store lifecycle is not part of the proposed shipping interface.

The initial failures led to concrete fixes. Staticlib exports and saved-link replay now materialize ordinary ELF where required; compact dependencies also work with noncompact consumers and rustdoc. ELF reconstruction preserves native alignment and bounds padding, with the [alignment harness](harness/alignment_correctness.py) checking 64-byte, 4 KiB, and 16 MiB alignments through BFD/LLD and staticlib boundaries. The final shared parser rejects authenticated section descriptors whose lengths disagree with ELF headers, preventing a downstream slice-copy panic; the compiler validates bundled-library section sizes too. The authenticated mismatch reproducer failed before and passed after the fix; [its receipt](correctness/descriptor-size/receipt.json) is explicitly local unit evidence, supplemented by the later native Wild runs above.

Several failures were test-environment or observability issues. Release compilers compiled out the original debug reuse event, so the dedicated opt-in reuse tracing target now emits at info level. The worktree harness initially enabled that logger globally, which correctly disabled Cargo cache/seed admission; removing it restored actual seeding without weakening the donor-independence checks. One normal unmount was transiently busy; a verified ordinary retry succeeded, and the harness now allows bounded ordinary retries without force or lazy detach. Wild tidy/discovery tests initially lacked clang-format, Taplo, and LLD; the passing receipts record the installed versions. A compiler test using the stage1 sysroot's absent `rust-lld` was adjusted to request system BFD explicitly.

Distribution validation also failed because the copyright generator looked for the sibling path dependency in Cargo's vendor directory. Rust `0cb1dbd9ea72906892c3a981f38c0b34a23152aa` now collects those notices, and Wild `dba82ebe` includes package-local copies of the unchanged upstream Apache and MIT licenses. Rust `e55e0485` additionally pins the already tested Cargo `207626090` gitlink. The [notice regression failed before](correctness/license-scraper/before.log) and [passed after](correctness/license-scraper/after.log); the complete copyright tool also [passed the focused test](correctness/license-scraper/full-tool.log). The [package-license receipt](correctness/package-license-receipt.json) records byte-identical upstream notices and unchanged codec sources. These changes do not alter compiler or linker runtime code after Rust `c6137ac` / Wild `8969b04e`. The license-only Wild rebuild produced the same binary hash; final rustc archive verification checks both the bundled Wild licenses and the shared crate's actual notice text in `COPYRIGHT.html`.

The first final fixture attempts all stopped at `E0463` (missing `std`): [Cargo](correctness/cargo-lifecycle-final-missing-std.json), [worktree](correctness/worktree-correctness-final-missing-std.json), and [alignment](correctness/alignment-correctness-final-missing-std.json). `x.py dist rustc` recreated the stage1 sysroot without the standard-library component, and the manual test-sysroot copy followed that packaging step. The rustc component archive itself was correct. Restoring the separately built standard library, verifying unchanged driver bytes, and passing the ordinary smoke test fixed the assembly; all three fixtures then passed on fresh cases. The failed receipts remain preserved and are excluded from passing coverage.

The [worktree harness](harness/worktree_correctness.py) intentionally requires the identified, retained Btrfs image and refuses an existing mount or case directory. It preserves fixture data and checks the loop backing file before teardown. The receipt's command paths describe the devbox run; reproducing elsewhere requires updating the owned fixture path and identity, not blindly mounting or deleting those paths.

The final source review found a separate CI setup blocker: Rust's unconditional path dependency requires the sibling Wild checkout even with compact mode disabled. CI-only commit `484aee036ae` places Rust at `source/rust` and pins Wild `dba82ebe99d98adbfe6358215d456cdddb1877da` at `source/wild` for both formatting/tidy and compiler jobs. It updates the shell working directory and the workspace-relative `hashFiles` check, preserves `contents: read`, and requests a read-only App token restricted to `ohm-wild` without persisting its checkout credentials. YAML parsing, shell syntax, and both checkout layouts were checked locally; the workflow has not run.

**CI credential setup remains required.** The read-only GitHub API review confirmed that `astral-sh/ohm-wild` is private and that `ohm-rust` currently has neither repository-level nor inherited organization Actions secrets or variables. Expose the coordinator's `OHM_RELEASE_APP_CLIENT_ID` variable and `OHM_RELEASE_APP_PRIVATE_KEY` secret to `ohm-rust`, and ensure that App's installation has read access to `astral-sh/ohm-wild`. The App installation grant was not verifiable through the reviewed repository metadata. The default repository-scoped `GITHUB_TOKEN` cannot supply that private cross-repository access. No repository settings or credentials were changed during this work.

The reviewed release scope is the binary `x.py dist extended` installation, including standard-library `rust-src`. It does not publish the full `rustc-src` source tarballs or `rustc-dev` compiler-source component. Those source packaging paths still omit the external shared crate and need corresponding packaging work before they can be offered as complete compiler sources. This limitation does not block the current binary release scope.

This evidence covers Linux x86-64. The release workflow checks out the shared crate beside Rust on both Linux and macOS, builds and bundles Wild only on Linux, and carries a versioned capability marker only with the source-built fork. Historical binary-only Wild bundles have no marker and cannot enable Cargo's compact mode. The macOS compiler and full optimized release distribution have **not** been built by this validation. Source/schema review and focused tests are not substitutes for those builds, nor are these controlled compiler builds PGO release-performance evidence.
