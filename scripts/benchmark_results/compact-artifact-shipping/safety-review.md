# Independent shipping review

Reviewed Rust `c16f0169220bbd3a9694b08becc1f00c30f60322`, then the CI-only credential remediation `d59f1c63326e874185ed4ec5bb052f384745110f`; Cargo `4a2813050da607ca5cfe7b5cf3a17ba7c9676be1`; Wild `b997fe077b81d3ff147e77d603f66fc5142aa3be`, then workflow-only `9fbf96f8b0ced108ea3f90c2341a289b16363ff7`; coordinator `48c8750f4b1b22b5bb2a4178cadd456faab8c5db` (PR #140). This was a source/interface review, with the existing portable evidence checked as supporting validation. No devbox activity or additional runtime proof is implied.

Result: no remaining shipping blocker found for the default-off, native x86-64 Linux Cargo opt-in and binary distribution scope. One credential-design finding was identified and fixed before this conclusion. This is not a claim that arbitrary hostile object files cannot exhaust process resources, nor a formal verification or fuzzing result.

## Finding fixed

**High: do not make a write-capable release App private key available to PR workflows.** Rust c16 CI referenced `OHM_RELEASE_APP_PRIVATE_KEY` in both PR token steps. Limiting the derived token to read access does not restrict the private key's authority: an editable same-repository PR workflow could use that key to mint another token. [Remediation d59f1c6](https://github.com/astral-sh/ohm-rust/commit/d59f1c63326e874185ed4ec5bb052f384745110f) changes both steps to a dedicated `OHM_SOURCE_APP_*` pair, documents an App installed only on `ohm-wild` with `contents: read`, and retains explicit read permission and nonpersistent checkout credentials. The release environment's existing credentials remain separate. This was a latent configuration hazard: the missing repository credentials prevented these token steps from running, and this review found no evidence that the release key had been exposed. The source change was inspected; no App, secret, installation, or repository setting was changed. CI's missing dedicated credentials remain an operational setup prerequisite, not a reason to copy the release key.

## Reviewed invariants

- **Malformed compact objects and reconstruction.** [CompactObject::parse and checked section reads](https://github.com/astral-sh/ohm-wild/blob/9fbf96f8b0ced108ea3f90c2341a289b16363ff7/compact-artifact/src/lib.rs#L356) validate index checksums, physically present descriptor tables, checked ranges, codecs, contiguous payload extents, section/block bounds, exact decoded lengths, and payload checksums. Metadata is capped at 256 MiB and individual payload blocks at 1 GiB. The final checked accessor rejects ELF `sh_size`/descriptor mismatches before decoding or slice copying; Wild, reconstruction, and Rust's native-bundle extraction use it. The earlier checksum-valid malformed-descriptor failure is preserved in `correctness/descriptor-size/`; the final source keeps its fix. These checks provide integrity/error handling, not source authentication. [unpack_elf](https://github.com/astral-sh/ohm-wild/blob/9fbf96f8b0ced108ea3f90c2341a289b16363ff7/compact-artifact/src/lib.rs#L728) preserves `sh_addralign`, rejects non-power-of-two alignment, limits physical padding to ELF table alignment, skips NOBITS payloads, checks arithmetic, and uses fallible reserve. Large alignment therefore does not directly multiply file allocation. Aggregate linker memory is not capped; selected blocks and reconstructed archives can still be large.
- **Lazy reads and ownership.** Payload initialization is synchronized by `OnceLock<Result<...>>`; the linker arena retains each `CompactObject` and its backing input for the lifetime of borrowed views. Decoded boxed bytes remain owned by the object. The optional mapped-cache path writes a private temporary file completely, verifies size and digest, and creates a read-only mapping; page eviction advises the immutable file-backed mapping without invalidating slices. `Arc`/`Weak` bookkeeping does not free storage behind borrowed bytes. I found no new unchecked cast or borrowed-slice lifetime escape. The optional cache's budget tracks advised residency, not a strict process RSS limit.
- **Publication and shared inodes.** [atomic_write/link_object](https://github.com/astral-sh/ohm-wild/blob/9fbf96f8b0ced108ea3f90c2341a289b16363ff7/compact-artifact/src/lib.rs#L845) create unique scratch entries, never truncate the destination inode, and rename complete bytes into place. Failure removes only owned scratch paths. Cross-device sharing copies to a new scratch file. [Incremental packing](https://github.com/astral-sh/ohm-rust/blob/d59f1c63326e874185ed4ec5bb052f384745110f/compiler/rustc_incremental/src/persist/work_product.rs#L41) explicitly replaces the output inode before hardlinking the saved product; existing compact products are only read/linked. This protects donor/worktree artifacts. Publication is atomic for readers but does not claim power-loss durability (`fsync` is not used).
- **Cache identity and prefix reuse.** Cargo retains compact and codec flags in unit rustflags/fingerprints; only the exact generated suffix is removed for cache-admission inspection, without teaching admission to trust user-supplied opaque flags. Late profile and `cargo rustc` tuning remain fingerprint inputs and suppress the generated fast default. The opt-in also selects globally embedded metadata. Rust compact options are tracked session inputs. Metadata prefix reuse still requires the previous dependency closure, metadata fingerprint, stable crate identity, source layout/protected spans, exact definition spans, compatible target modifiers, and valid suffix ranges before writing a fresh temporary inode. Public changes or failed validation fall back to encoding; saved late metadata is recreated after reuse. Existing corruption/invalidation/late-error checks support these paths.
- **Exports and cleanup.** [Archive construction](https://github.com/astral-sh/ohm-rust/blob/d59f1c63326e874185ed4ec5bb052f384745110f/compiler/rustc_codegen_ssa/src/back/archive.rs#L822) packs only the compact rlib lane and reconstructs compact members before ordinary archive/symbol editing. [Ordinary consumers](https://github.com/astral-sh/ohm-rust/blob/d59f1c63326e874185ed4ec5bb052f384745110f/compiler/rustc_codegen_ssa/src/back/link/compressed_artifacts.rs#L24) materialize dependencies in an owned `MaybeTempDir` that survives linking, preserving late metadata/native-bundle selection and avoiding basename collisions. Rlink object retention follows explicit replay lifetimes. Shipping rlibs use normal ar plus raw metadata and contain no manifest/store dependency; ordinary Cargo clean/cache/worktree ownership rules apply. The external-store experiment retains separate lifecycle assumptions and is not enabled by the shipping opt-in.
- **Capability and unsupported configurations.** [Cargo's opt-in selection](https://github.com/astral-sh/ohm-cargo/blob/4a2813050da607ca5cfe7b5cf3a17ba7c9676be1/src/compiler/ohm_linker.rs#L16) defaults off, requires a native x86-64 Linux host/target and the exact versioned marker beside bundled Wild, and rejects explicit driver/linker overrides, cross-crate/plugin LTO, packed split DWARF, external-store/format overrides, and disabled metadata embedding. Late profile/cargo-rustc and applicable build-script arguments are rechecked; ordinary native args and paired `-Xlinker` forwarding remain accepted. Rust independently rejects unsupported format targets/LTO/packed DWARF before incremental object replacement. The marker is a distribution compatibility contract, not adversarial authentication; replacing trusted toolchain files or environment tools is outside this guard.
- **Build and package provenance.** Source mode verifies the pinned repository, exact clean commit, and sibling shared crate both before and after a locked build; the selected toolchain, Wild version, binary digest, licenses, and capability marker are recorded. Binary-only historical bundles do not receive the marker. The release workflow checks out Wild beside Rust on Linux and macOS, but builds/bundles Wild only on Linux. Bootstrap copies the marker into the linker directory and explicitly removes a stale marker when packaging a binary-only payload. The unconditional crate has actual macOS compiler/check/link/run coverage in the retained receipts. Full rustc source tarballs/rustc-dev packaging still omit the sibling crate and are explicitly outside the reviewed binary release scope; a future source distribution must address that.
