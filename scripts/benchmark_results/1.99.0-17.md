# Ohm 1.99.0-17 source studies

## Ruff checks after a build-script edit

After reversing a historical Ruff build-script change, the next unchanged `cargo check --locked` recompiled `ruff`, `ty`, and `ty_wasm`. Using the timestamp of the validated build-script result kept all 520 units fresh. The median for that unchanged check fell from 1.00 s to 0.62 s. The experiment compared matched release-profile Cargo builds with and without the fix on the -16 Cargo source. The table summarizes 24 independent pairs on that source. [Cargo #256](https://github.com/astral-sh/ohm-cargo/pull/256) · [Raw results](https://github.com/astral-sh/ohm-cargo/tree/ea1c411d2a4bceb7e059550b8feb752ee7c5b9d4/benchmarks/ruff-dev-loop-20261027/build-script-timestamp-current-results)

| Ruff workload                                | Paired time reduction | 95% interval |
| -------------------------------------------- | --------------------: | -----------: |
| First unchanged check after the edited check |                 35.7% |  28.9%–41.8% |
| Edited check and first unchanged check       |                 16.8% |  13.6%–20.1% |

The edited check alone had no clear timing difference. All three affected build scripts still ran after the edit. A separate typeshed edit regenerated the expected Pydantic contents. [Generated-data controls](https://github.com/astral-sh/ohm-cargo/tree/a206c6ada1df84f587618baf5b952ee3d433b40a/benchmarks/ruff-dev-loop-20261027/build-script-timestamp-current-qualification)

## Reusing procedural macro expansions

On the published -16 compiler, six of 28 downstream builds failed with `E0460` when the test mixed artifacts from different macro-cache histories. The fix restores virtual source files and syntax contexts on a cache hit. Ordinary Rust callers built successfully across both histories in the Ruff parser and `ty_ide` checks. [Rust #238](https://github.com/astral-sh/ohm-rust/pull/238) · [-16 reproducer](https://github.com/astral-sh/ohm-cargo/tree/db71638cbb6dda4752d51ca6373e234811dff18f/benchmarks/ruff-dev-loop-20261027/shipping-16-macro-results)

On a Ruff parser edit, the compiler stayed within the study's 3% instruction-overhead bound with both retained and empty incremental state. Wall time was less certain. For empty state, the estimate was 0.25% slower, with a one-sided upper bound of 17.67%. [Instruction counts](https://github.com/astral-sh/ohm-cargo/tree/b43e22221f444367608cfd82c71504b941bdcdfd/benchmarks/ruff-dev-loop-20261027/proc-macro-source-replay-v3-instructions-results) · [Wall times](https://github.com/astral-sh/ohm-cargo/tree/30d53f05dfbacd0e7fdbf88759cc758b6783439d/benchmarks/ruff-dev-loop-20261027/proc-macro-source-replay-v3-overhead-results)

## Checksums for input filenames

On released Ohm 1.99.0-16, a space in an input path could make rustc hash a different file. Cargo could then reuse a stale executable or accept an invalid check. Distinct filenames that printed identically could cause the same problem. The revised -17 pairs the compiler fix with a Cargo change that retires unsafe checksum records. [Rust #241](https://github.com/astral-sh/ohm-rust/pull/241) · [Cargo #258](https://github.com/astral-sh/ohm-cargo/pull/258)

The corrected Cargo was replayed on 14 retained workspaces with the released compiler. All seven builds produced the clean binary's result, and all seven invalid checks produced the clean compiler's full diagnostic. On already-built Ruff workspaces, the first upgrade recompiled 71 of 520 check units, 68 of 501 build units, and 162 of 619 test-build units. The second command in each workspace ran zero compilers, build scripts, or linkers.
