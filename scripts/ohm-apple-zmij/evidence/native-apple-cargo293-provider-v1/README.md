# Apple native-provider evidence with Rust #276

On one local APFS Apple-silicon host, Cargo #293 detected an unannounced higher-priority static library, its malformed replacement, and its removal. This held when the CRC-independent vector assembly appeared in the executable or a Rust dependency. The consumer printed 29 instead of 17, and both invalid states returned Cargo 101. Exact signed -20 Cargo protected the declared inputs and genuine Rust edits. With the two native directories deliberately unwatched, signed Cargo reused its prior executable in all three no-Rust-edit cases. Both binaries used the same Rust 444c compiler, the same SDK, and actual Xcode ld. [Run 41065239483](https://github.com/astral-experiments/ohm/actions/runs/41065239483)

All nine genuinely unchanged provider controls with an existing seal launched one link-only rustc and skipped Xcode ld. Both placements detected in-place 29→17→29 archive replacements while size, inode and mtime were fixed. When the only marker came from the root executable’s own assembly, the first full compile learned it too late to install the native-link driver. Its first unchanged command ran stock ld to create the seal. A transitive marker let Cargo create the seal on the prior full compile. The actual stamp and repeat transitions are in `native-decisions.json.gz`. The seal contains a 32-byte action/product digest and previously emitted linker stderr. It does not store a replayable native input graph for a Cargo-before-rustc hit. [Driver installation](https://github.com/astral-experiments/ohm-cargo/blob/735e1528ed741015c57676dccf05dbdc0ff7bed1/src/compiler/mod.rs#L1634-L1658) [Receipt validation](https://github.com/astral-experiments/ohm-cargo/blob/735e1528ed741015c57676dccf05dbdc0ff7bed1/src/compiler/native_link/relay.rs#L100-L148)

In a third placement, a genuine vendored registry library bundled the 17/29 C object into its Rust rlib. Both Cargo versions correctly rebuilt two Rust units and ran one native link even on the unchanged control. The malformed or missing archive failed in the bundling rustc before the final linker. Good outputs expose the selected `provider.o` digest. A final ld receipt alone cannot prove what an upstream archive producer consumed.

In the focused `ruff_python_ast` test build after Ruff #28335, the ordinary environment gave 0 full / 1 link-only / 0 Xcode ld on both Cargo #293 repeats, each an authenticated receipt hit. Signed Cargo had 0/0/0. Both ordinary roles compiled and linked the genuine edit and repair once, rejected E0425, and matched all 53 or 54 test names, actual test results and whole Mach-O bytes against independent clean builds at the same paths. A separate minimal-shell diagnostic changed the raw image across clean restarts. All 19 raw differences (14 provider and 5 Ruff) were accounted for by seven-character incremental `.rcgu.o` suffixes in actual Xcode-linked `N_OSO` object names and the CodeDirectory page hashes covering them. All original signature pages validated. This post-hoc byte attribution preserves the strict raw-identity failure.

The native stack compared original Cargo commits 2d44bd4a and 735e1528. Cargo #293 was built once in release profile from 3,114 verified source entries with `ohm-defaults` and `all-static`; it did not use distribution PGO. There are 548 real Cargo commands, 66 independently reopened native executables and 4,556 files in the original 20,027,082-byte artifact. This was a functional study. No wall-time inference was registered.
