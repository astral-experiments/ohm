# Native Apple-silicon Ruff qualification

This job asks whether accepting the register-only NEON assembly comment in zmij avoids a full compilation and halves the first unchanged Ruff build after a real source edit. Everything runs on one checked-out branch using ordinary single-session Cargo and rustc defaults.

## Dispatch

Use the existing packaging CI workflow on the private QA branch. The signed pilot uses its own repository's read-only release token and public Ruff source. The compiler run recovers both exact Rust commits from the public Rust ancestor and the adjacent verified source bundle. The job needs no credentials for the sibling fork.

```sh
gh-auto workflow run ci.yml --repo astral-experiments/ohm \
  --ref charlie/qa-apple-zmij-packaging-native -f apple_zmij=mechanism

# After the signed pilot succeeds on this same CI commit:
gh-auto workflow run ci.yml --repo astral-experiments/ohm \
  --ref charlie/qa-apple-zmij-packaging-native \
  -f apple_zmij=qualified -f apple_pilot_run=PREVIOUS_RUN_ID
```

The pilot uses `macos-15`, which GitHub documents as an Apple M1 with three cores, 7 GB RAM and 14 GB storage. It preserves an observer or capacity failure. An 8 GiB free-space check precedes distribution installation and a 6 GiB check precedes each Ruff validation. The Apple archive is 294,960,329 bytes. Its envelopes contain 1,429,419,086 bytes of regular files. The three installed components total 404,547,483 bytes, and only those components and the installer's top-level files are unpacked. The qualified job uses `namespace-profile-macos-15`, the runner used by Ohm Rust's compiler CI. It requires more than 32 GiB free for the source bootstrap, and more than 8 GiB before every measured installation. The job records physical RAM, filesystem availability and the sum of free, inactive and speculative VM pages. It checks those pages before starting each build phase. Both work areas are private to the job. [GitHub runner specifications](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)

## Counters and process coverage

The counter calibration runs a known 200-million-iteration, two-instruction ARM loop in the measured process, its child and its grandchild, each against zero work, three times per depth. Raw `/usr/bin/time -l` output is retained. A whole-tree instruction total is reported only if all three increments lie within 10% of 400 million. The CPU column has its own roll-up test. Otherwise the primary elapsed result remains available, with the actual scope recorded. Apple's implementation calls `proc_pid_rusage` on the direct child and obtains CPU accounting separately through `wait4`. [Darwin time source](https://github.com/apple-oss-distributions/shell_cmds/blob/main/time/time.c)

The full native observer uses the kernel's Endpoint Security exec events. A genuine Xcode native link establishes positive coverage, including argv, actual linker identity and a real runnable program. Each foreground session is start-gated and ended with a second kernel-observed sentinel. Sequence numbers must be contiguous. Only selected argv, executable identity, code-directory hash and process IDs are recorded. The observer is absent from all timed Cargo commands. [Apple exec events](https://developer.apple.com/documentation/endpointsecurity/es_event_exec_t) and [dropped-event detection](https://developer.apple.com/documentation/endpointsecurity/es_message_t/seq_num)

If the host denies access, the receipt keeps that failure and runs foreground Cargo without hooks. A separate untimed diagnostic wrapper checks the real compiler inode, forwards the original argv and inherited jobserver file descriptors, and waits for the actual child's status. Its outputs and typed rosters must agree with ordinary Cargo. This fallback cannot observe successful linker processes. Their count stays unknown, and it cannot admit the twelve-pair inference. A failure in the fallback preserves the earlier unwrapped evidence.

## Prospective decision

The executable under measurement is `cargo +ohm build -p ruff_python_ast --locked --offline -j4 --message-format=json`. Each installation starts independently with empty target and shared-build directories and a new writable clone of the verified package cache. Rustup, the checkout, the selected compiler, the registry, and the artifact/search paths have fixed visible locations. The three consecutive measured calls cover the first edit, its immediate unchanged repeat (**primary**), and one further unchanged repeat. The controller uses a blocking wait and a separate watchdog. It clones the returned rlib using macOS `clonefile` so the three native readers and all payload scans can run after the window. Cold warm-up is retained separately.

Two independent paired installations run parent/child and child/parent. The twelve-pair confirmation opens only if both first unchanged ratios are **greater than 2**, all native and type/error checks pass, a whole zmij compilation disappears, and neither additional native work nor extra links appear. Each confirmation pair starts from new empty stores. Six run parent first. The fixed balanced order has rank 695 among 924 possibilities, selected from SHA-256 of `ohm/Apple-zmij/confirm/1:<release archive digest>:<Ruff edit>`. The second block is independent of the first two installations; the pilot observations are kept separate.

Each endpoint includes per-pair absolute times, ratios and medians. For twelve independent primary ratios the distribution-free 96.14% median interval uses ranks 3 and 10. The sharp 2× null also undergoes an exact one-sided period assignment test over all 924 balanced allocations. The primary must have lower median bound above 2 and p ≤ .05. The first edit and further repeat are reported separately, including adverse observations. No additional cohort or endpoint is selected after seeing the results.

Portable receipt checks run with `python3 -IB scripts/ohm-apple-zmij/run.py test_protocol -v`. A local Mac with the same staged assets can call the individual `pilot`, `prepare` and `cohort` commands from the workflow via the same dispatcher. Only the isolated job's finished scratch generations are retired. Compressed Cargo streams, per-visit source/product identities, native events, all timings, bootstrap bindings, independent reader binaries and failures are retained in the upload.
