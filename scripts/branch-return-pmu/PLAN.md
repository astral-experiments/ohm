Keep the registry, immutable input contents, checkout path, SDK path, Cargo home path, effective environment, thread and job settings identical. ## Decisions fixed before the pilot

For F and K separately, use same-host same-SDK off instructions divided by on instructions on **return-A** and **return-B**. For the two-return round trip divide the sums, never average individual ratios. Separately report first B plus first return, cold installation plus both revisits, unchanged, erroneous invocation, repair, and absolute instructions. Report allocated bytes at first B, settled B and after repair against each SDK's own off, and K-on versus F-on. The packed-on versus full-on instruction contrast is a cost tradeoff and secondary. Never pool the two different SDKs as independent replications of retention.

The pilot is a feasibility gate. For a same-SDK 2x candidate, every return in both directions on both independent boots must be at least 2.00x, with all correctness and metering controls admitted. Report cold/first-use costs and observed storage, including regressions. There is no assumed acceptable disk overhead. The user decides the tradeoff from measured bytes. A passed F or K can proceed independently after both pilot reports have been inspected. Do not use this pilot to claim statistical significance.

If justified, freeze a subsequent balanced 12-pair cohort using independent worker boots before dispatch, with its endpoint, two directions and cycle, exclusion policy, machine model and order frozen. A 2x claim requires the lower end of a paired 95% interval for the primary round-trip ratio above 2, disclosure of the per-direction results, and independent replication. Predeclare how the interval will be computed and how indeterminate runs are handled before that cohort. A failed native, exact-clean, metering or inventory control withholds the affected cohort. A failed pilot endpoint is reported without a new product PR for that claim.
