# What the 14 fresh Rust table pairs cost on a Ruff repair

This diagnostic asks how many inherited user instructions change when the candidate cannot create the first output of its private two-stream writer after the known parser error. It measures the entire instrumented repair on the same compiler. It includes the failed create, raw-file preservation, subsequent work and the diagnostic observer itself. The result does not measure exclusive instructions inside the encoder, and does not establish a product speedup.

## Two repair commands per host

Position 01 runs pass then block. Position 02 runs block then pass. Each uses its own fresh GNU boot, separate from the four original structural/counter boots. The same native observer library, canonical configuration filename, absolute owner list and inherited environment are used on both repairs. The mode byte in that file selects the intervention. No hook is installed globally. Calibration, preparation, subsequent ELF/typed checks, file census and decompression run outside the repair counters.

The interceptor authenticates the physical Cargo, rustc and stock Wild executable using the opened process image's device and inode. It saves their original argv and the mapped physical Rust driver and identical diagnostic DSO. It delegates unrelated `open64` calls to libc. In the block arm only, the registered compiler receives EACCES at an `O_RDWR|O_CREAT|O_EXCL` graph creation immediately inside a registered owner's private `s-…-working` directory. The pass arm calls libc normally. Both observe the previous pair and actual restoration into this build’s private directory. A tagged accounting row in block balances the second evidence write in pass. That row is not a query creation. This is an ELF-loader diagnostic covering the named physical executables, not a general tracer of every descendant. The invocation itself still performs the real final link and native execution.

The first create precedes all graph/query encoding in rustc_incremental. Failing it returns from the pair writer; the subsequent native object compaction is an independent call. The ordinary switch predictor, RUSTFLAGS, selection/decoding of the previous checkout and downstream codegen/link behavior must continue to match. On each repair require the following.

* Exactly 16 full Rust compilers, bound to their actual working owner by argv, incremental root and table I/O, and one physical stock Wild producing the returned Ruff inode. Both arms must have identical compiler argv by crate and kind. The bin and library named Ruff are checked separately.
* Both source streams are actually opened at the registered physical old filename, device, inode and length. The selected same-checkout donor must match source ordering over the two previous finalized sessions. A newer other-checkout session exists for exactly the 14 switched crates. Both raw restore destinations must be successful creates under the single working prefix that eventually finalizes, in the same compiler process and before any targeted fresh create. Rust generates a different working name on a restore retry.
* Exactly the 14 registered first creates and no other fault. Pass creates both streams, whose initial file identities become the actually published packed files. Block prevents the first create and produces no second create. All 14 must change representation; the other two owners must keep their raw pairs. Both raw names and build aliases must refer to the same inode. The independent two-root GNU stat ledger must show exactly the same 16 newly published directories and the precise physical identities of all tables and objects.
* Parse each compact table header, session credential, size, RSIC magic and complete zlib stream. Reopen every freshly published object, including the embedded session/name/length of every compact object, verify BLAKE3 and SHA-256 of its decompressed ELF, and record SHA-256, size and blocks of its stored file. The same owner, object name, physical storage class, complete native bytes and size must survive in pass and block. Both must match the historical 748 compact and 918 raw object counts and all 16 per-owner counts. Complete warm CLI and independent native reader must match the edited empty byte for byte. Contradictory layout and real parser controls remain mandatory.
* Record fresh logical table sizes and inner SHA-256 separately. Independent sessions can contain different serialized bytes even with identical native products. A difference exceeding 2% of the larger logical stream for any owner, or 1% of the larger aggregate for either stream, makes this attribution inconclusive. Report every unequal logical table SHA. Byte differences in a native product or object refuse the comparison.
* Keep the qualified inherited `plain` counter unchanged, its original kernel calibration and all raw clock fields. Each repair requires positive instructions, zero hardware error and exact `running == enabled`. No counters run on the training steps. On each boot report pass minus block as an unscaled, signed whole-command difference. The historical 41.16–41.17B E/C repair difference is separate. No positive threshold or hypothesis test is defined for these two observations.

Native original ZIPs, worker identities, complete raw kernel image observations, libc events, file inventories, original ELF bodies, positive and negative CLI output, and calibration are required. Missing or disparate evidence leaves the diagnostic unresolved. The script retains partial raw receipts on a failed step.
