### Why this uses a rustc-only dynamic loader

The ordinary `-Zllvm-plugins` interface changes codegen input tracking on this released compiler. In a one-package control, the original pass via the explicit flag rebuilt an untouched binary. Cargo reported that the checksum for `/dev/null/ohm-untracked-relink-inputs` was missing. Unwrapped old, edit and repeat compiled 1/1/0 times. Adding the explicit flag compiled 1/1/1, with the same complete old and edited ELFs and executable results 29 and 36. That loader is excluded.

The private QA wrapper and loader instead register the identical constructor through `dlopen` in the actual signed compiler process. The loader verifies its own process's physical frontend and resolved LLVM, then clears `LD_PRELOAD` before returning to rustc. Every successful kernel exec checks that no native child inherits it. All experiment arms use the original compiler argv. A real local admission verified 1/1/0 true rustcs and 1/1/0 signed Wilds across bare, sham, original and guarded builds, including full old/edited ELF equality. Every fresh worker independently repeats that admission. A per-compiler stderr side copy identifies actual guard calls by kernel PID; Cargo can replay cached stderr on a fully fresh native command. The counter includes the receiver's C wrapper, small diagnostic relay, native Rust and all of Cargo's children/threads. The external process tracer and all after-command hashing/native execution are outside the PMU. The original and guard probes have different diagnostic output volume, which is included. Concurrent guard reason lines can interleave. The verifier counts only complete eight-field records and records unmatched prefixes.

The four assignments, gates and sole primary endpoint are fixed in `schedule.json`. Each pair starts from independently empty compilations, checks against a plain same-boot historical edit and a second selected independently empty build, and reports both directions' raw counts. Two exploratory pairs per workload do not establish statistical significance. This is a QA loader comparison. An exact uninstrumented compiler pair would be required for a product claim.
