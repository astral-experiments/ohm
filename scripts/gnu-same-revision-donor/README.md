# Native GNU source qualification for bounded packed Git refs

This one-worker, manually dispatched workflow compares the published QA compiler D (d95494a6a63c) with its direct source child P (70a0f8090d1e), using the same stage0, CI LLVM, source tree paths, bootstrap command, original Cargo 761 and stock Wild. It records no performance endpoint. The protected release and Ruff test jobs run independently.

The frozen a3333161 importer reopens the official source job 41303656721/124839568474 and both original artifact digests, restores its complete 81-member E SDK, then creates D from the measured one-file overlay. The original 12-test log is reopened. The 19,166-byte parent and 19,715-byte child Git packs have nine objects each and no external source credentials. All production changes descend from the genuine D tree. The only changed files are rustc_incremental's fs.rs and fs/tests.rs.

After building P with the original unmodified ./x stage1 command and preserving its reconstructed 81-member SDK, the worker runs the complete rustc_incremental unit suite (12 genuine D tests plus one new test). It replays the same suite on all of D's original production tree with the exact new test body and a test-module shim naming D's literal 65,536-byte constant. D must execute the assertion and return None instead of the matching revision. It then restores the exact P sources, re-executes all 13, runs the unmodified packed branch cache, opt-out, and missing-query-cache run-makes, reassembles stage1 and checks that not one SDK byte changed. Expected allocations are one new stage bootstrap, D/P/E SDKs (about 727 MiB each), and one retained delta (driver and matching rustdoc only if changed). The original full bootstrap had a 32 GiB free-space entry guard, a 2m37s build and 1.65 GiB per-process MAXRSS. A live guard still applies; these are historical observations.

The independent source reader checks the literal argv, cwd, raw process status, named test counts, old failure's precise values, initial and restored pass, transplanted source bytes, sets of actual SDK files, full hashes, modes, independent inode identities and compressed overlay. A failed step preserves originals available at the time, and cannot qualify a candidate. The final two artifacts are packed-ref-source-and-driver (P/overlay and raw source/test logs) and packed-ref-sdk-and-resources (E/D/P SDK inventories, original enrollment and capacity). Inputs carry contents/read and actions/read only.

Offline: python3 -IB scripts/gnu-same-revision-donor/reopen.py SOURCE_RECEIPTS SDK_AND_RESOURCES. Pass a third argument only on the live host to verify complete original physical SDK identities. To reconstruct P offline using a complete previously authenticated D directory, run python3 -IB scripts/gnu-same-revision-donor/overlay.py SOURCE_RECEIPTS/P/overlay SDK_AND_RESOURCES PARENT_D NEW_PRIVATE_P. Paths require a private empty destination. Raw full-Ruff donor and duration comparisons, if commissioned, are separate.

After the reviewed source job succeeds, fetch both official ZIPs once and replay from this exact QA checkout with python3 -IB scripts/gnu-same-revision-donor/receive_source.py RUN JOB SOURCE.zip SDK.zip PRIVATE_TEMP_DIRECTORY. This uses gh-auto read-only from the pinned checkout, requires the sole original job and both official checksums and successful stages, verifies the raw retained assertion, source and overlay, and compares its independently reconstructed report to the actual archived live source verdict.
