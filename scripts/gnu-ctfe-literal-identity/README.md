# GNU qualification for private CTFE allocation identity

This one-job, manually dispatched source qualification compares the authenticated original compiler 393b4b05a4bfa3f531a36023846f86236a6b71a9 (E) with its direct child df2c077a113a709ab379c8ec34e62c94c7513325 (C). It collects no performance endpoints. The proposed scope is the new renderer-independent allocation fix, with default ordinary Cargo flags and the branch cache off. A result requires all the following gates.

1. Restore E from the original [successful source job](https://github.com/astral-experiments/ohm/actions/runs/41242910474). The inherited official locator and reader check the job, the two API SHA-256s, both complete source ZIPs and all 81 installed files. Strict Cargo is 761ea115605c34f11a1cd29afd68812c1e1359dd and the stock Wild binary SHA-256 begins 0d6335808b64. The E driver SHA-256 is f20d40da3f9365b0d3544ad76136e8c1036a6d1a5ecb39281e972f782fa33ae6.
2. Materialize the source using the established public bootstrap transport, then the same-repository signed-state Git object transports. Validate E, the seven changed source paths, all twenty child objects, the parent and child tree identities and each changed blob. The source checkout needs no credential to another private repository. Build only C, using the original E working directory, exact target/options, stage0 rustc and Cargo digests, original LLVM and unchanged stock auxiliary programs. The authoritative native entrypoint is `bootstrap_subject.py build SOURCE TRUSTED`. The previous confirmed argv is in `inputs/bootstrap.json`.
3. Compare the 81-file GNU kit. C must change the driver and may also change rustdoc. Independently copy/hash the C members, save only the changed compressed member(s) as an overlay, then reverify the decompressed size, bytes and permissions before running tests. Successful reconstruction from an existing genuine E SDK uses `python3 -IB overlay.py SOURCE/C/overlay WORKLOAD_ORIGINALS E_SDK EMPTY_DEST`. An overlay from a later-refused source job is an unqualified diagnostic. `native-qualified.json` is written only after all native source gates.
4. Run the real project compiler units and `tests/run-make/rdr-public-hash-ctfe-literal-identity` plus `incremental-missing-query-cache` with `./x`. The first unit requires the actual original salt-zero allocation ID, rejects equal-but-distinct, nonzero-salt, writable and relocated entries. The new run-make exercises warm/empty public hash, an empty versus moved pointer and native clients. The latter existing run-make covers missing or unconsumable cached results. The two ordinary Cargo collision runs (eight visits each) change only the middle byte of a 257-byte CTFE allocation, test cyclic statics, four transitions and a fresh independent B. The selective hash collides but full content and the native result must distinguish 17 and 29. For migration, both SDKs alternate at the same alias with the exact same forced incremental version stamp. Physical generation 8 and 11 headers, their respective own-cache loaded witnesses, both incompatible-cache rejections, and real two-way cross-rlib consumers must all pass. This measures neither migration cost nor retained bytes.
5. Run `cargo +ohm build -p ruff_python_ast --lib --locked --offline -j2 --message-format=json` on the genuine A b5dba861cc38e3f7fb4524c9ceba3e01a474ea13 and B 7b13f01ba1569887a25670820764b24c206da8e5. The A→B source history contains 169 changed paths, nine in the target crate. Seed all 505 checksum-bound locked archives. For each compiler require A cold → B edit → immediate B repeat → separately empty B at the same source, target, build, and stable compiler paths. Each command must return the 36 original complete Cargo target/features/profile roles and five build-script roles. Their physical outputs must remain under the two designated paths. Its three real native proc macros and all 94 digest-bound compiler object payloads must match. The independent Rust client exercises Expr 64→56, actual extension dispatch, and an opposite-width client with the precise E0308 at its own source.
6. Open each actual separate .rmeta and the precise stable-key RDR table against the archive's actual root listing. The original must reproduce the existing warm/empty public-hash drift and 10,150 changed reachable item hashes. C must have zero of those differences and the exact clean public hash. Both checks require the same stable/path/reachability set, private/global hashes, 17,431 reachable definitions, all 18,142 keys, and all 3,589 expansion identities and values. A fresh Cargo repeat keeps the full input and previous metadata bytes. Full warm-versus-empty .rmeta/.rlib equality is reported independently. The stable IDs can occupy different encoding slots. The byte differences and corresponding complete bodies stay available for further examination. `archive_fields.py` verifies both occurrences of the compiler temporary suffix for every exact CGU in the GNU archive and its genuine .rmeta-link Rust string list. It compares native payloads by their actual stable CGU identity and order. The 188 suffix occurrences are retained in the originals. No section or member is ignored to fabricate raw byte identity.
7. `reopen.py SOURCE_RECEIPTS WORKLOAD_ORIGINALS` reopens complete raw bodies and counts, independently parses the archive and listing, reruns the retained native client for each distinct ELF, checks cross-compiler effects and the physical source-generation evidence, and prints a JSON verdict. The explicitly separate artifacts are `ctfe-identity-source-and-driver` and `ctfe-identity-ruff`; partials are uploaded at any refusal. Consumers can bind a final result to its actual GitHub attempt, job, artifact identities and SHA-256s. This workflow has no release environment or publication permissions.

## Rehearsal and proposed trigger

From the repository root, run `python3 -IB scripts/gnu-ctfe-literal-identity/test_qualification.py`. With a physical Rust product repository, `python3 -IB scripts/gnu-ctfe-literal-identity/binding.py RUST_REPO` authenticates the full child source and transport without compiling. `baseline_reference.py PRIOR_AST_RECEIPTS` opens the genuine historical E first B, independent empty B and return/repeat as separate observations. Its negative controls include a changed object byte, a single changed archive-name token, and substituted baseline policy refusal controls.

The single Linux job accepts only workflow_dispatch, attempt 1, the literal QA ref and an independently reviewed head equal to GITHUB_SHA. An authorized reviewer can dispatch the locally reviewed commit after it is published on that QA ref:

```sh
gh-auto workflow run ci.yml --repo astral-experiments/ohm \
  --ref charlie/qa-ctfe-literal-identity-20261101 -f reviewed_head=EXACT_QA_GIT_SHA
```

A green source and this single structural workload would establish correctness only for the observed cases. Actual timer/counter or broader Cargo skip qualification remains a separate decision.
