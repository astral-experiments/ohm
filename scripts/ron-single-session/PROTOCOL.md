# One incremental session for a forced native registry check

This is an unscored feasibility screen. It tests whether conventional rustc incremental analysis can pay for itself when Cargo already has to recompile Ron. The altered compiler invocation and its private session are specific to this experiment. The whole historical edit and the first unchanged check are reported separately. An unchanged operation here is a fresh ordinary Cargo process.

## Existing result and code

The frozen signed regular Linux check on Ruff `93526150df078af7dd8fc4226cdcc469539d2001` selected Ron 0.12.0 (`default,std`), 338 units and 303 returned artifacts. On the first unchanged check the complete command retired 2,541,466,454 user instructions, 1,756,795,215 of them in Ron. With all other work held fixed Ron must finish in at most 486,061,988 instructions to halve the whole. The historical edit plus its first unchanged repeat has a 1.79× upper bound even if every Ron instruction vanished. It had 16 nested native derives and zero loads from a persistent query cache. The original recorder omitted function arguments. The six paired Serde derives and four extra local `Deserialize` derives are source-derived identities. The new off-clock profile enables function arguments. Cargo explicitly disables incremental compilation for registry sources after working out profile overrides. Rustc therefore opens neither an incremental graph nor its on-disk query cache. Its ordinary resolver still runs expansion, then `typeck_root` and `mir_borrowck` are eligible for serialized result reuse when there is a session. The signed toolchain includes the same two resolver source blobs as Rust #278. #244 disabled cached derive outputs and #245/#259 fixed foreign source-byte/span handling. ## Subjects and decisions frozen before the hosted run

Both arms use signed Linux `1.99.0-21` rustc `c79998a5cd143c445a4b2528f20953b176a65c5d`, native driver `dae4f8dc64b2b2ac9dc04dfe2cfad633d6af1a87da2dfc532e757ffe758680e3`, and the identical source-built repair-qualified Cargo `b76dc8006155d48a8cd7d6c5543acb9c18e2ce4b`, ELF SHA-256 `f1a88bf5fb2bf431eeea068455d9d4e98dcfbfee3dc381ee47cc7c96df3e128f`. The signed baseline had a stale E0308 upon repair. The common Cargo substitution keeps that error independently testable in this pilot. [Disposition of the common binary](https://github.com/astral-experiments/ohm/actions/runs/41149649623/job/124383410439)

Use one otherwise idle hosted Linux x86-64 VM with an actual working per-process user-instruction PMU, at least eight schedulable CPUs and 60 GiB entry scratch space. One installation per arm, sham then session, on identical paths. Use the same C exec wrapper in both. Only the Rust process for `ron-0.12.0/src/lib.rs` with `--emit=dep-info,metadata` gets `-Cincremental=<canonical private session>` on the session arm. It applies from training onward. Ordinary macro execution stays enabled on both. Every native argv and returned diagnostic is retained. All 28 calibrated syscall-counter controls must pass. Report measured training cost and logical/physical allocation of every file in the one additional session, with device/inode deduplication. There is no second retained checkout, no macro output replay and no experimental native linker change.

Each arm performs cold training, one genuine reverse application of `32c5cd5daba51d9c3da691c5b43afa6a7a4bb731`, two unchanged checks, E0308, exact repair, another unchanged check, a separate native macro/cache profile and a fully empty edited check. Prior generated target, shared and session directories are retained separately. Frozen operation `cargo +ohm check -p ty_project --tests --locked --offline -j8 --message-format=json`. Two independent real external readers accept the valid Ron API and reject the bad typed result. Warm and empty same-mode Ron metadata and external reader output must match literally. Record any cross-mode metadata differences, require equal typed inventories, actual macro location/name data and all compiler diagnostics across arms. Repeat must run exactly one real Ron compiler and zero native links on each arm. A clean reference is mandatory. The actual fixed DSO control separately changes 17→29→invalid output→17 with a fully warm directory and a distinct empty comparator on each visit, verifiably rerunning the binary macro exactly once each time. All eight calls, E0308, diagnostic equality and real executable results must pass.

The whole-command user-instruction ratio must be at least 2 on both preselected repeats, with physical native and storage gates intact, to justify independent balanced confirmation. This is an engineering screen with one installation per mode. Two dependent repeats cannot establish a release speedup or confidence interval. Should the gate fail, preserve the cause and all raw rows. A fixed-artifact download that no longer exists exits before acquisition. A profiler run never contributes to the whole-command ratios. No preparation or comparison changes the shared Git/Ruff checkouts.

## Hosted runner command

In a disposable checkout, supply these four immutable inputs. `STUDY` is this directory, `PROTOCOL` is `astral-experiments/ohm` at `9d1dd09be4d2346142957cc298093d8a75c755c3`, `SIGNED_READER` is the same repository at `f40b16cdb9c041c941a5e339f816111a80a84bdf`, and `COUNTER` is its `scripts/ohm-gnu-syscall/calibrate.c` at `927e20bcad028e5ed4290a58bd330a258ee5da41`. The frozen original workflow supplies the package provenance, GitHub Actions checkout/action versions, 16-core hosted runner label, GitHub release/attestation access and software requirements. [Exact original hosted setup](https://github.com/astral-experiments/ohm/blob/9d1dd09be4d2346142957cc298093d8a75c755c3/.github/workflows/ci.yml#L10-L55)

```sh
set -eu
python3 -IB "$STUDY/acquire-cargo.py" "$RUNNER_TEMP/repair-qualified-cargo"
python3 -IB "$STUDY/study.py" --protocol "$PROTOCOL" --signed-source "$SIGNED_READER" \
  --counter "$COUNTER" --cargo "$RUNNER_TEMP/repair-qualified-cargo/cargo"
python3 -IB "$STUDY/verify.py" "$RUNNER_TEMP/ordinary-ron-check/packet" > "$RUNNER_TEMP/ron-screen-verdict.json"
```

The first step uses GitHub Actions' read-only `GH_TOKEN`; the second takes its own read-only `QUALIFICATION_TOKEN`, removes it before compiling and uses the signed reader's isolated environment for all Cargo/rustc processes. The original signed release and its genuine whole-Cargo PMU results remain separate from this source-fixed pipeline. Preserve `$RUNNER_TEMP/ordinary-ron-check/packet`, `ron-screen-verdict.json` when produced, and `repair-qualified-cargo/custody.json` including on failure. No native inputs from these artifacts enter a product.
