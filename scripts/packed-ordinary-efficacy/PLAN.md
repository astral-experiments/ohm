# Packed branch cache on the full Ruff CLI

This is a new two-machine screen registered before collecting instructions. It measures the complete ordinary Cargo command. The earlier process census and its refusals are a separate experiment. None of its instruction data enter the screen.

Build Ruff A `b5dba861cc38e3f7fb4524c9ceba3e01a474ea13` and its 169-file edit B `7b13f01ba1569887a25670820764b24c206da8e5`. Run `cargo +ohm build -p ruff --bin ruff --locked --offline -j4 --message-format=json`. Both arms use the exact packed compiler `0afbeff303d3658bff52582d8f1a996d59e6c8ce`, strict Cargo `761ea115605c34f11a1cd29afd68812c1e1359dd`, the same stock Wild, 505 locked archives, and identical paths. Only K-on requests the opt-in branch cache. The historical baseline and candidate have separate empty target and build directory histories.

On each new boot, first build both branches from empty for each arm. Run the native archive and real Ruff Unicode provider controls, including replacement at preserved inode, size and mtime, malformed input, removal, and clean builds. Then run a complete ordinary unmetered history for each arm. Repeat with freshly emptied roots under the calibrated inherited hardware user-instruction counter. Position 01 runs off before on and position 02 reverses that order. Each history runs cold A, first B, return A, return B, unchanged B, a real invalid edit and repair. Require the real E0308 and keep actual stderr. For every successful build require the complete 375-unit graph, correct real Ruff and typed-client behavior, and byte equality of both ELF files against their own independent empty build. In both arms check equivalent clean executable segments and loaded bytes. Preserve the source and exact effective environment for each invocation. Require the retained allocated-byte ledger for every phase. Record the complete SDK inventories before and after both histories.

Use the existing eight-CPU nested-process and thread hardware calibration and require at least 99.5% scheduling coverage per observation. Do not scale counts or substitute elapsed time. Keep the stdout, stderr, source state, typed unit inventories, counter readings, and before-and-after provider verdicts. Compare both unmetered and metered actual outputs and dirty rosters. Review the raw artifacts independently before reporting ratios. No new process census is part of these ordinary-command data, so they cannot establish how many physical links were skipped.

For the exploratory screen, each boot must clear 2.00× on each of its two return commands individually and on their sum. The denominator is the on-arm count. Report both orders, cold and first switch costs, unchanged, invalid and repair, and the allocated-byte difference including the first switch. If the screen passes, confirm on two disjoint cohorts of 12 native boots, with six per order in each cohort. The primary confirmation statistic is the paired ratio of sums of the two return commands within each boot. For each cohort require the third ordered ratio of twelve to exceed 2.00× (the two-sided third-to-tenth exact median interval covers 96.14%). No sample from this screen enters confirmation. A pass is specific to returning to a previously built branch. Storage and performance are separate decision criteria.
