# Does rustc halve an ordinary Ruff renderer edit on default GNU/Linux?

Registered after two unchanged-compiler profiles and before a native candidate build or any candidate counter. A prior two-host study measured 5.827–5.828 billion retired user instructions for the changed library. The parent regenerated six of 42 LLVM objects. The remaining 36 reused their original on-disk objects. A signed-parent notebook replay independently identified another real rendering change. ## Hardware decision

Use process-inherited retired user instructions for the whole Cargo invocation including all child processes and threads, running at full duty with no multiplexing. Require the existing workload-bound calibration, nested-process and multi-thread controls, plus official per-host identity, counter ABI and raw inputs. Use the untraced arm for admission. Collect kernel attribution in a separate witnessed run. Each host tests both compilers on fresh, separate, equally initialized physical directories mounted at the same logical names. Build the dependency or application tree only from the enrolled sources. Witness four Cargo units, one ordinary selected rustc on a true edit, zero on the first unchanged visit, and zero native linker invocations for this library workflow. Counts from a worker attribution stream must never be added to the overlapping whole count.

* First use two fresh hosts in opposite order to screen P versus C. Include F as a separately labelled attribution arm and run the fixed holdout. Stop if either corrected primary-edit P/C ratio is below 1.8, any behavioral gate fails, or a new full rlib, session or saved link payload is retained. A screen cannot qualify a PR.
* Enroll two independent cohorts of exactly 12 fresh host pairs. Each has six preassigned two-host blocks, one P-first and one C-first per block. The second cohort is conditional on the first passing. All host boots must be distinct, including screen boots. Keep every position and failure visible. Separate the chosen original edit and holdout on each host. Never share build outputs between compilers. No host replacement after observing counters, pooling, elapsed-time substitutions, or changing the primary endpoint.
* Primary endpoint is whole-command P/C on the **changed** source-map library build. Report all 12 within-host ratios, median and ordered third/tenth interval (96.14% under independent host sampling), exact one-sided sign probability against two with ties excluded, and raw lane medians. Each cohort must have its own lower bound above two. Report the same statistics for cold, repeat, their sum with edit, the separate notebook edit, and any F comparisons actually run. A first-repeat or combined result cannot replace the primary.
* In each cohort require the third/tenth upper bound on C/P to be at most 1.05 for the original cold and unchanged commands and all three notebook commands. In each workload the median increase in unique physical target plus shared build allocation must be at most 5% and at most 2 MiB, measured separately when warmed and after an independent empty corrected build. No second complete output or incremental session may be retained. Extra individual CGUs count toward the limit. Report product sizes, including raw rlib and installed compiler deltas, even on a miss.

Only open a GNU performance draft if both cohorts and all semantic, storage and independent replay gates pass. Publish the raw counts and a reproducible reader. If a gate fails, report the observed failure and preserve its evidence. A revised compiler or an additional edit requires a new prospective registration.
