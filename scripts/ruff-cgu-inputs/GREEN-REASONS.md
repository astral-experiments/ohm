# Why a Ruff workspace codegen unit rebuilt

The signed GNU build of Ruff's 169-path AST change emitted 49 workspace codegen units. The ordinary preoptimization bitcode and complete native objects of 48 units matched both revisions and independent empty builds. That archive contained no prior dependency graph or work-products table, so it could not explain the decision to recompile. [Original study](https://github.com/astral-experiments/ohm/actions/runs/41362345812)

The observer takes the incremental directory from the actual `ruff_workspace` rustc argv. In each of the ordinary observed and saved-bitcode histories, it freezes every completed workspace session after B, again immediately before the A command, and after A. It retains the dependency graph, the build and check graph checkpoints when present, and the work-products table. Every other regular file, including every possible donor object, has its exact filename, inode, timestamps, size and SHA-256 recorded. The two pre-A inventories must agree. Commit-pinned installers and the original Cargo histories check the changed, empty, invalid and repaired native outputs.

Graph indices identify nodes within an individual captured graph. Comparisons across compiles must use the dependency kind and 128-bit key and preserve duplicate entries. A prior graph and donor inventory can establish availability of previous inputs. Identifying the first rejected dependency also requires observation of the signed compiler's actual color or query-forcing decision.

This run is diagnostic. Its outcome is a physical reason for recompilation with the original branches and final products attached; it has no treatment or performance admission.

A sixth independent history uses a passive VEX probe only in the selected signed `ruff_workspace` compiler on the edit. Cargo has already chosen the frontend, arguments, dependency paths and jobserver descriptors when the observer stops that process. First it freezes the prior workspace donor inventory at the actual exec boundary. A one-shot loader then restores every original argument and environment byte, checks each inherited descriptor and starts the observer. The signed compiler performs its own work-product reconciliation, recursive green walk, query forcing and native code generation.

The reader checks every captured dependency edge against its exact prior sparse index. For cross-session comparisons it retains all matching current indices and fingerprints. It reports ambiguous matches and repeated edge ordinals. Each claimed available donor is independently decoded from the signed work-products table and joined to the physical saved files. The native object sets and literal first-edit compiler arguments must agree with the ordinary observed history. Each real no-reuse decision must match an actual new LLVM input in the separate saved-bitcode history. The complete CLI and its typed consumer must still match their independent clean builds.

The published GNU -22 compiler's driver digest is `4c8ccf0072e8f382a3a3756fd60e46936a2bd206996201c55caffe58d29725db`. A four-crate source control changed a parser constant from 17 to 29. The compiler received its real prior native object, encountered an already-red `optimized_mir` dependency, rebuilt the object, and changed the linked output from 34 to 58. The next cosmetic edit reused the result. Two independent comparison histories produced the same workspace objects and linked executables.

Additional native controls preserved a real `global_asm!` veto, recognized an exact donor file withdrawn after publication, and verified a green PostLto reuse. The probe covers the published compiler's regular and cold executable sections.

The private descriptor handoff uses a fixed record of 24 fully assigned bytes. The kernel, loader and VEX client independently check access direction as well as identity. Both Cargo jobserver pipe ends share an inode. The fixture confirms one read-only and one write-only endpoint. The loader unlinks the handoff before the diagnostic starts, and the artifact omits this internal file on every exit.
