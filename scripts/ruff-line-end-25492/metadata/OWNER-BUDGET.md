# Which original Ruff #25492 compilers could change the whole build?

Only `ruff_linter` is large enough by itself to remove 20% of the **61,066,244,767** ordinary Cargo instructions. It accounted for 9,387 hardware samples, an estimated 23.468B instructions. Reaching 20% would require eliminating about **52% of the entire linter compilation**. The next largest pair without the linter, `ruff_server` and `ruff_python_ast`, totaled an estimated 9.883B against a 12.213B target. [All compiler and native source identities](owner-budget.json)

The two largest consumers together accounted for an estimated **28.633B**, below the **30.533B** saving required for 2×. The independently metered sampling run retired 60.970B instructions, of which 2.610B were outside the sample-period total. These are observed budgets. They cannot rule out an effect hidden in the unsampled work.

Across the linter and server, the foreign metadata/green union covers **1,491** distinct observations, or 3.728B estimated instructions. Expanding the union to every recognized incremental query decoder and proc-macro/expansion stack gives **3,589** or 8.973B. Both counts include every dependency. No sampled frame was named `external_metadata_input_hash`. A zero count cannot establish zero cost. The groups use each original 4 KiB stack once per union and leave the unclassified observations intact. In the server, even 20% of that single compiler would require removing about 97% of the 428 observations in the narrower union. [Physical samples and named source functions](owner-budget.json)

The full CLI supplied twelve changed retained workspace inputs to each compiler, alongside other external arguments. The linter already retained the physical OLD inode and bytes of **254/256** CGUs. One further object was regenerated byte-identically. Its 200,240-byte `24hdueqpruf9yj3et7jm3a65y` object changed. The server changed its 2,228,104-byte `4t939guk7r9kldlc2gel8afb6` object among 215. Each complete edited set matched its independent clean set. All 200 AST objects held the same bytes in every state, although its complete rmeta changed. This original packet retained object hash/name records but no raw object, dependency graph, query profile or rmeta for the linter or server. It cannot name the responsible provider for either changed object. [Ordinary physical donors](../ordinary.json) · [Exact OLD, edited and clean hashes](owner-budget.json)

The actual source offers a reason to distinguish these endpoints. The linter's `Locator::line_end` delegates to the unchanged `LineRanges` string implementation. The database's notebook JSON-diagnostic renderer calls the edited behavior via `source_code.line_end_exclusive`. The server explicitly converts all three variants of the source-file `PositionEncoding` enum. The original recording does not establish which metadata fields the server asked rustc to decode for that conversion. Its ordinary read set therefore cannot inherit the small host consumer's 484/484 result.
