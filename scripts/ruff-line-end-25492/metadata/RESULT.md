# What an ordinary Ruff host compiler read from the edited crate

On Ruff #25492, **all 484 query-result fingerprints guarded by the host library's dependency on `ruff_source_file` stayed identical**. This held from OLD to the edit and from edited to independent clean NEW. There were zero added, removed, duplicate, missing-hash or zero-fingerprint rows. The compiler still observed the new public crate hash. [All 484 stable keys, results and original graph digests](actual-reads.json)

The consumer was the host `ruff_python_trivia` library used by `ruff_macros` in an ordinary `cargo +ohm build -p ruff --bin ruff --locked --offline -j4`. The original #253 Linux SDK compiled the real CRLF fix. Its consumer accounted for **62 of 23,344 hardware instruction samples** in the full edited build. Twelve of those 62 stacks touched any recognized metadata decoder or query green-validation/forcing function, across all dependencies. The 4 KiB unwind and sparse counts limit attribution. These counts establish neither a 20% improvement to this compiler nor a material saving on the 61.066B-instruction CLI. ## Producer hashes and prior implementations

Of the 484 stable ordinary returns, **208** had an unchanged per-definition reachability hash, **251** had a changed one, and **25** lacked a matched per-definition hash or definition key. A per-definition gate alone would recover only part of this boundary. Equal returned fingerprints do not compare arbitrary lazy table payloads or authorize reusing the entire consumer output.

An earlier producer-only study retained real OLD, edited and independent NEW metadata for the other `get-size,serde` feature identity. It matched all 858 definition keys, recovered 786 per-definition reachability hashes and reported 72 missing. OLD to edit changed 464 of the 786 hashes and zero of 39 upstream crate entries. All 50 hashes in `line_ranges` stayed equal, while 81 of 157 in `newlines` changed. Of 16 preselected AST-facing definitions, all 16 kept the same decoded definition and identifier coordinates, and 14 kept the complete source bytes inside the definition span. The two edited method bodies differed. Across all recoverable coordinates 58 definition spans and 38 identifier spans moved. Some spans were absent or undecodable. The producer-only study's feature closure differed from the full CLI's featured provider, so it supplies no direct observation of `ruff_python_ast` or `ruff_linter`.
