# A source-only split for the real Ruff #25492 producer

The edited CLI's `ruff_python_ast` invocation had 1,887 instruction samples in the archived run. All its 200 native object payloads survived the edit unchanged. Its two direct source imports are `LineRanges` and `UniversalNewlineIterator` in `helpers.rs` and `whitespace.rs`. The defining `line_ranges.rs` and `newlines.rs` are unchanged. The actual compiler also received changed `ruff_python_trivia.rmeta` and a changed `ruff_macros.so`. Unchanged imports by themselves prove neither that rustc did not read other items nor that the proc macro would produce the same expansion.

Before rebuilding an AST consumer, build only the real `ruff_source_file` provider with its ordinary consumer configuration (`get-size,serde`). Cap the whole Cargo unit graph at 80 units. Capture OLD, edited NEW and an independent empty NEW from the original proposal #253 compiler, running the registered Unicode/CRLF native witness in each case. Preserve the entire rmeta, stable IDs, Cargo graph, literal provider argv, actual output files and own/dependency hashes. Compare the producer subtree and argv with the enrolled CLI and surface any mismatch. A narrow feature graph cannot be represented as the original CLI graph.

The reader is derived from the signed notebook metadata-field decoder. The Rust #253 source pins the root-layout field sequence, all 88 metadata tables, 17 definition-key kinds, wire version 10 and Ohm metadata epoch 3. Compare public per-definition rows by stable definition-path hash and resolved definition path. Keep expansion and crate-global values separate. The physical hash for an individual definition already includes everything the reachability graph assigned to it, including applicable locations. If relevant names and their methods have identical rows while the root changes, the producer split merits a reader-specific diagnostic. If they change, or the table cannot be decoded, retain that outcome. Neither one authorizes a whole-compiler skip without evidence of actual reads, sound fallbacks for negative/crate-wide/diagnostic inputs, and competent treatment of proc macros and native outputs.
